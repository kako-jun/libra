# Libra — 要件仕様（正本）

この文書が Libra の最上位要件である。他の docs と食い違う場合はこの文書を優先する。

## 1. 想定利用者と前提

- 汎用品。特定の個人向けではない
- 利用者本人は**ほとんど動けない**。上下左右の選択もできない
- 本人ができる操作は、**時間で移動するカーソルが目的の項目に来たときに、スイッチを1回オンにすることだけ**（シングルスイッチ自動スキャン）
- この操作（キー/外部スイッチ）だけで、Libra のすべての伝達機能が成り立たなければならない。タイルの直接タップは追加経路で、これに依存してはならない
- 画面を読むのは、そばにいる家族・介助者・看護師（人間）である

### 1.1 基本姿勢

- **レベル制にしない**。「できたね」など上達を促す演出・表示をしない。快/不快・はい/いいえ・定型語・スキャン・文字盤・モールス・触覚出力は段階ではなく**入口の違い**であり、使わない機能があってよい
- 最小の目的は「話せるようにする」ことではなく、**不快を伝えられる / 快を続けられる**こと
- 第一対応端末は**タブレット**（縦横両対応）。スマホでも動く
- 高価な福祉機器を前提にしない。**安価な市販デバイス**（家電量販店・100 円ショップの Bluetooth シャッター等）を前提にする

## 2. 安全の優先順位

伝達内容には命に関わる順の優先度があり、**カーソルが早く届く位置ほど優先度の高いものを置く**。

1. **緊急**
2. **はい / いいえ**
3. **不快**（痛い・苦しい・体位など）
4. **快・要望**（続けて・やめて・もっと・変えて・大丈夫・ありがとう・気分など）
5. **文字盤**（自由作文。最後の手段）

自由作文を定型プリセットより前に置いてはならない。遅い経路の奥で緊急が遅れると死の危険がある。

## 3. シングルスイッチ入力

### 3.1 スイッチ

本人の入力は次の2経路だけ。

- **キー / 外部スイッチ**: キーボードのキー押下（Space / Enter / 音量キー等を含む任意キー。キーリピートは無視）と Bluetooth シャッターボタン（OS/ブラウザに届くキー入力として受ける）。どれも同じ1つの「オン」で、**現在のスキャン対象を実行**する（§3.2）
- **タイルの直接タップ / クリック**（主ボタンのみ。右/中クリック・ペンのバレルボタンでは実行しない）: 押した**そのタイル**を、スキャン枠の位置と無関係に実行する。スキャンのカーソルは時間で動き続けており、押したタイルとは独立
- **画面の背景（タイル以外。タイル間の隙間・パディング・メッセージ欄を含む）へのタップ / クリックは何も実行しない**。タイルのヒット領域はタイル要素そのものだけ

実行は pointerdown（押した瞬間。下限・離して決定の設定があれば §3.3）で行い、続いて届く click は無視して二重実行しない（pointerdown を伴わない支援技術の合成 click だけはフォールバックとして実行する）。モールス画面（§4.7）の押下は符号になる入力（緊急は SOS）なので、キー / 外部スイッチだけで行う（モールス画面ではタイルは表示されない）。

本人に「戻る」「上下左右」などの別入力を要求しない。

### 3.2 自動スキャン

- **起動時からスキャンが動いている**。本人が開始操作をする必要はない
- カーソルは一定間隔で次の項目へ進み、末尾の次は先頭へ戻る
- キー / 外部スイッチがオンになった時点でカーソルが乗っている項目を実行する（タイルの直接タップは押したタイルを実行する。§3.1）
- 項目を実行したら、画面遷移先の**先頭項目からスキャンを再開**する
- 伝達（メッセージ表示）が1つ完了したら、**ホーム画面の先頭（緊急）に戻る**
- スキャンを止める設定は本人の経路に置かない（止まると本人は再開できない）

### 3.3 誤入力対策（介助者が設定）

| 設定           | 内容                                                                  | 既定値              |
| -------------- | --------------------------------------------------------------------- | ------------------- |
| スキャン間隔   | カーソルが次へ進むまでの時間                                          | 1.5 秒（0.5〜5 秒） |
| 先頭待機       | 画面を開いた直後、先頭項目に留まる時間                                | 間隔の 2 倍         |
| 連打無視       | 直前のオンから一定時間内のオンを無視する                              | 0.5 秒（0〜3 秒）   |
| 押下時間の下限 | この時間以上押し続けたときだけオンとみなす。押している間は進捗を表示  | 0 秒（0〜2 秒）     |
| 決定タイミング | 押した瞬間 / 離した瞬間（下限があれば、押した瞬間は下限に達した時点） | 押した瞬間          |
| 聴覚スキャン   | カーソルが進むたびに項目名を短く読み上げる                            | OFF                 |

押下時間の下限・決定タイミングは、キー・Bluetooth シャッター・タイルの直接タップのすべてで同じ判定が効く。押しっぱなし中にスキャンが進んでも、決定するのは**押し始めの対象**（キー / 外部スイッチはカーソルが乗っていた項目、タイルの直接タップは押したタイル）（押下中に画面が変わった、または同じ画面でも項目の並びが変わって押し始めの項目がその位置になくなった場合は、別の項目を実行せず無視する）。

設定は localStorage（ルートキー `libra`）に保存し、再起動後も保持する。

## 4. 画面構成と巡回順

各画面の項目は上から（スキャン順に）並べる。以下の項目名にある「→」は**下位画面へ進む項目である旨の記法**（本文書内の表記）であり、実際の画面表示は矢印文字ではなく山形アイコン＋中身の予告行で示す（DESIGN.md §2 参照）。

### 4.1 共通規則

- ホームは「緊急」を先頭に置く。ホーム以外の通常下位画面は「戻る」を先頭、「緊急」を2番目に置く。深い画面の途中でも緊急へ最大1周以内で届く
- 緊急詳細は、すでに緊急状態が成立した後の詳細入力画面である。重複する「緊急」タイルは置かず、「戻る」を先頭に置く
- 緊急詳細は「戻る」の次に未選択の詳細候補を置く。ここから「戻る」を選んでも緊急状態は解除せず、親画面へ戻る
- 伝達を1つ完了した直後の1周だけ、ホームの緊急の次に「取り消し」を出す（直前の表示を1つ前に戻す）
- 1画面の項目数は少なく保つ（目安 8 項目以内）。多い場合は2段階（グループ → 項目）にする

#### 4.1.1 画面階層の正本

以下の木が、本人画面の全 `ScreenId`、親子関係、通常の戻り先の正本である。`←` は「戻る」の遷移先を表す。`urgentDetail` を除く全本人画面には、現在位置から緊急状態を開始して `urgentDetail` へ移る共通分岐がある。緊急状態そのものは画面階層に属さず、どの画面へ移っても上部の専用領域に残る。

```text
本人画面
└─ home（ホーム）[先頭: 緊急]
   ├─ urgentDetail（緊急詳細）← home [先頭: 戻る / 緊急タイルなし]
   │  └─ 選択後: 詳細を緊急状態へ追記して home
   ├─ discomfort（不快）← home [先頭: 戻る → 緊急]
   │  ├─ discomfortOther（不快・その他）← discomfort [先頭: 戻る → 緊急]
   │  └─ painLocation（痛い場所）← discomfort [先頭: 戻る → 緊急]
   │     └─ painIntensity（痛みの強さ）← painLocation [先頭: 戻る → 緊急]
   ├─ moodRequest（快・要望）← home [先頭: 戻る → 緊急]
   │  ├─ requests（してほしいこと）← moodRequest [先頭: 戻る → 緊急]
   │  └─ feelings（今の気持ち）← moodRequest [先頭: 戻る → 緊急]
   ├─ letters（文字盤・行）← home [先頭: 戻る → 緊急]
   │  ├─ lettersRow（文字盤・文字）← letters [先頭: 戻る → 緊急]
   │  └─ lettersYesNo（文字盤・はい/いいえ）← letters [先頭: 戻る → 緊急]
   └─ morse（モールス入力）← home [構造上の先頭: 戻る → 緊急]

全本人画面の共通分岐（urgentDetail を除く）
└─ 緊急を選択 → 緊急状態を開始・継続 → urgentDetail

介助者画面（本人画面の ScreenId・スキャン階層には含めない）
└─ 介助者メニュー（常設: 見出し / 緊急解除 / 閉じる → home。その下に全画面幅の上部カテゴリタブ）
   ├─ タブ「状態」: 画面スリープ防止 / オフライン準備 / 全画面
   ├─ タブ「スキャン」: 間隔 / 先頭待機 / 連打無視 / 押下時間 / 決定タイミング
   ├─ タブ「入力方式」: 聴覚スキャン / モールス入力
   ├─ タブ「フィードバック」: 音声 / 振動
   ├─ タブ「表示」: 文字サイズ / 明るさテーマ / 高コントラスト
   ├─ タブ「フレーズ」: 不快 / 不快・その他 / 痛い場所 / 要望 / 気分
   └─ タブ「データ」: 書き出し / 取り込み / 設定を既定に戻す
```

メニューの追加・削除・親変更・戻り先変更を行うときは、実装だけを変更してはならない。この木、各画面の案内、`PARENT_SCREEN`、全画面を列挙するメニューテストを同じ変更で更新し、コードより先に不自然な階層を検査する。

#### 4.1.2 画面上部の情報設計

本人画面では、異なる意味の情報を同じ表示領域へ混在させない。

| 表示領域       | 表示するもの                                                                            | 表示しないもの                                     |
| -------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 緊急状態       | 未解除の主文「緊急です。来てください。」と、明示ラベル「伝えた状態:」に続く選択済み詳細 | 操作候補、通常の後続伝達、履歴を想起させる「最新」 |
| 現在画面の案内 | 画面の目的、ここで選ぶもの                                                              | 直前の選択結果、技術的な状態文                     |
| 現在地         | ホームから現在画面までの短いパンくず。親画面へ戻ると親までの経路へ更新する              | 選択結果、緊急状態                                 |
| 採用した選択肢 | 最後に選んだ画面遷移・戻る・文字選択などを「選択:」と短く表示                           | 通常伝達、緊急主文・詳細、複数件の履歴             |
| 直前の伝達     | 本人が最後に確定した通常の伝達を「直前に伝えたこと」と明示                              | 緊急主文、緊急詳細、複数件の履歴                   |
| 入力中文字列   | 文字盤またはモールスで確定前の文字・符号                                                | 確定済みの伝達、緊急詳細                           |
| 操作候補       | 現在の画面で選べるタイルだけ                                                            | 選択済みの緊急詳細、現在地説明                     |

現在地は `PARENT_SCREEN` と `SCREEN_TITLES` から全 `ScreenId` について導出する。痛みの強さ画面では選択済みの痛い場所、文字段階では選択済みの行を経路に反映する。選択確認は通常伝達・緊急状態の表示と重複させず、新しい選択まで保持する。表示のための追加待機・入力は設けず、スキャンや直接入力のタイミングを変えない。

緊急状態は画面より上位の独立状態であり、介助者が解除するまで全本人画面の専用領域に表示する。緊急中に「はい」などを伝えても、緊急状態は上書きせず、後続の伝達だけを「直前の伝達」領域へ出す。

| ScreenId                         | 目的・上部案内                               | 選択または入力の結果                     |
| -------------------------------- | -------------------------------------------- | ---------------------------------------- |
| `home`                           | 伝えたいことを選んでください。               | 下位画面へ進むか、伝達してホームへ戻る   |
| `urgentDetail`                   | 緊急です。いま伝えたい状態を選んでください。 | 詳細を緊急状態へ追記してホームへ戻る     |
| `discomfort` / `discomfortOther` | つらいことを選んでください。                 | 具体化画面へ進むか、伝達してホームへ戻る |
| `painLocation`                   | 痛い場所を選んでください。                   | `painIntensity` へ進む                   |
| `painIntensity`                  | 「選んだ場所」の痛みの強さを選んでください。 | 伝達してホームへ戻る                     |
| `moodRequest`                    | 今していることへの希望を選んでください。     | 下位画面へ進むか、伝達してホームへ戻る   |
| `requests`                       | してほしいことを選んでください。             | 伝達してホームへ戻る                     |
| `feelings`                       | 今の気持ちを選んでください。                 | 伝達してホームへ戻る                     |
| `letters`                        | 文字の行を選んでください。                   | `lettersRow` へ進むか、入力操作を行う    |
| `lettersRow`                     | 入力する文字を選んでください。               | 文字を追記して `letters` へ戻る          |
| `lettersYesNo`                   | 質問への答えを選んでください。               | 伝達してホームへ戻る                     |
| `morse`                          | 短押し・長押しで文字を入力します。           | 入力・確定、またはホームへ戻る           |

介助者メニューは、緊急解除と閉じる（カテゴリ切替と独立して常に見える常設の行）と、全画面幅の上部カテゴリタブ（スマホは横スクロール、広い画面は均等配置。同一 DOM）、選択中カテゴリの設定だけを表示する設定ペインで構成する。タブは ARIA tablist/tab/tabpanel で、タブにフォーカスがあるときの ←/→/Home/End（修飾キーなし）だけがタブ移動に使え（打鍵なので無操作 60 秒タイマーは延ばさない）、Enter/Space を含む他のキーは従来どおり本人のスイッチ入力として扱いメニューを閉じる（§6）。メニューを開くたびに「状態」から始める。本人向けの画面案内・スキャン対象・`ScreenId` からは分離する（介助者メニューには専用の案内文を置かない。見出しとタブ名だけで足りる）。

### 4.2 ホーム

1. 緊急
2. （伝達直後の1周のみ）取り消し
3. はい
4. いいえ
5. 不快 →
6. 快・要望 →
7. 文字盤 →

### 4.3 緊急

- 選択した瞬間に「緊急です。来てください」を赤で大きく表示する。**緊急警告音は鳴らさない**（周期音が #32 の「コンコン」の一因と疑われるため(病院を連想させる不快さも含む)。Issue #43）
- 誤報の害より見逃しの害が大きいため、**確認手順を挟まない**
- モールス入力（§4.7）中は、SOS（・・・－－－・・・、短点3・長点3・短点3の連続9押下）でも緊急になる。確定を待たず9つ目を離した時点で即座に緊急にする
- 表示後、任意で詳細（苦しい / 痛い / 息ができない / 吐きそう / 胸が痛い）を追加できる
- 緊急詳細の候補には、すでに成立している状態と重複する「緊急」タイルを置かない。選択済み詳細は候補欄へ重ねず、上部の緊急状態領域に「伝えた状態:」として表示する
- 緊急中の後続伝達は、曖昧な「最新」表示や履歴として緊急主文へ混ぜず、「直前に伝えたこと」領域へ1件だけ表示する
- **緊急表示は介助者が解除するまで残る**。本人のスイッチ入力で上書き・取り消しされない
- 緊急は**介助者が解除するまで、画面上部の静かな視覚表示で残る**。音は出さない（振動は §7.1 のとおり）
- **再読み込み・再起動後も、解除まで復元される**（緊急状態を localStorage の `libra:emergency` に保存。有効期限なし）。復元時は視覚表示を再開する。警告音は無いので、自動再生制限に関する案内表示も出さない

### 4.4 不快

1画面8項目以内の枠に収めるため、暑い・寒い・喉が渇いた・かゆい・眠れないは「その他 →」に退避する（4.4.1）。

戻る / 緊急 / 痛い →（場所: 頭・胸・おなか・背中腰・手足・その他）/ 苦しい / 痰を取ってほしい / 体の向きを変えたい / トイレ / その他 →

#### 4.4.1 不快・その他

戻る / 緊急 / 暑い / 寒い / 喉が渇いた / かゆい / 眠れない

#### 4.4.2 痛みの強さ

痛い場所を選ぶと、**強さの画面**へ進む（場所を選んだだけでは伝達しない）。

戻る / 緊急 / 場所だけ / 少し / かなり / とても

- 「場所だけ」を先頭に置く（強さを選べない・選びたくない場合も最短で伝えられる）。伝達文は場所だけ（例:「胸が痛いです」）
- 少し / かなり / とても は、場所の全文の「痛いです」の前に強さを入れる（例: 不快 → 痛い → 胸 → とても =「胸がとても痛いです」）。「痛いです」を含まない（介助者が編集した）全文は、末尾に（とても）を足す
- 「とても」は緊急色（urgent トーン）。場所の色（胸=緊急色）は場所だけ・少し・かなりに引き継ぐ。緊急の警告音は鳴らさない（緊急は §4.3 の別経路）
- 6 項目で 8 項目以内を保つ

### 4.5 快・要望

戻る / 緊急 / 続けて / やめて / もっと / 変えて / 要望 → / 気分 →

- **二値の入口**「続けて・やめて」「もっと・変えて」を最上位に置く（本人は今の刺激や行為への好み・拒否を、これだけで伝えられる）。伝達文は「続けてください」「やめてください」「もっとお願いします」「変えてください」。はい・いいえと同じく**編集できない固定項目**
- これまでの要望は「要望 →」に2段階化した（8 項目規則のため）。要望: 大丈夫 / ありがとう / 眠りたい / 静かにしてほしい / 家族に会いたい / 話したい（通常下位画面の固定項目は §4.1 の戻る・緊急）
- **気分**（不安 / さみしい / 落ち着かない）を「気分 →」に置く。**独立の入口にしなかった理由**: ホームは 8 項目規則（緊急・取り消し・はい・いいえ・不快・快・要望・文字盤・モールスで上限）で増やせず、不快の画面（8 項目）にも入らないため、快・要望の中に置いた。気分も不快側の内容を含むが、身体の不快（§4.4）より優先度は低いと位置づける
- 要望・気分は介助者がフレーズ編集（§6.1）で追加・変更・並べ替えできる。テレビ・音楽もここに追加できる
- 快・要望の最上位（続けて/やめて/もっと/変えて と「要望」「気分」への遷移）は編集できない

### 4.6 文字盤

- 文字は**清音 46 字 + 長音「ー」**。濁点・半濁点・小書き文字は置かない（読むのは人間であり、「めかね」→「めがね」は文脈で補える。入力ステップを増やさないことを優先する）
- **2段階スキャン**
  - 行段階: 戻る / 緊急 / あ行 / か行 / さ行 / た行 / な行 / は行 / ま行 / や行 / ら行 / わ行 / 確定 / 1字消す / はい・いいえ →
  - 文字段階: 戻る（行段階へ）/ 緊急 / その行の文字（わ行は わ・を・ん・ー）
- 入力途中の文字列は常に画面上部に大きく表示する。そばの人が先読みして「○○？」と聞き、本人は「はい / いいえ」で答える運用を前提にする
- 「確定」で入力文字列をメッセージとして表示し、ホーム先頭へ戻る

### 4.7 モールス入力（上級者向けの逃げ道）

単一スイッチのモールス入力に慣れた人のための、文字盤より速い入力。学習負荷が高いため**既定導線にはしない**。介助者が設定で ON にしたときだけ、ホームの**最後**（文字盤の後ろ）に「モールス」が出る。

- **入力**: 短押し＝・、長押し＝－。長押しの境目は介助者設定（既定 0.5 秒、0.15〜1.5 秒）。押している間は、その時点で・と－のどちらになるかを表示する。#6 の押下時間の下限は雑音除去として効き（それに満たない押下は符号にしない）、長押しの境目はその下限より長くなる。連打無視（§3.3）はモールス中は適用しない（短点の連続入力を妨げないため）
- **文字の確定**: 最後にスイッチを**離してから**一定時間（既定 1.5 秒、0.5〜3 秒）無入力で、入力中の符号を1文字として確定する。**押している間は、文字の確定も語の区切りも無操作での復帰も進めない**（ゆっくり長押しする人の SOS の緊急が、押している最中の確定でばらけないため）。解放を取りこぼして 10 秒以上押しっぱなしになった入力は、符号にせず捨てる
- **案内は常に画面に出す（暗黙の操作を作らない）**: モールス画面には、短押し＝・／長押し＝－（境目の秒数）、緊急＝SOS（・・・ －－－ ・・・。待たずにすぐ）、・を5つ→待つとスキャンへ戻る、・を6つ→待つと1字消す、・－・－・－→待つと確定して伝える（操作の符号は文字の確定を待って実行され、SOS だけが待たずに即緊急になることを明記する）に加えて、時間で自動で起きること（文字の確定までの秒数・語の区切りまでの秒数・何も押さないとスキャンへ戻る秒数・SOS の数え直しの秒数・10 秒を超えて押しっぱなしの入力を無効にすること）を常時表示する。押下時間の下限（#6）が設定されているときだけ「◯秒未満の押下は数えない」を1行足す。押したら出る・設定で隠す・初回のみ、にはしない。秒数は介助者設定の値に追従する。本人はスイッチだけでスクロールできないため、**全項目がスクロールなしで画面内に収まる**こと（390×844・568×320・844×390・320×568 で確認）。収めるため、モールス画面では画面名の階層表示・直前の選択・直前に伝えたことの枠を隠し、案内の文字・余白・列数を画面サイズに合わせて詰める（レイアウトの数値は DESIGN.md §9）
- **語の区切り**: さらに無入力が続く（既定 4 秒、1.5〜8 秒。文字の確定より 0.5 秒以上長いことを保存値で保証する）と、全角空白を入れる（分かち書き）。1字消した後・該当なしの符号を捨てた後・画面に入り直した直後は、次の入力があるまで入れない
- **符号は和文モールス**（かな・濁点 ・・・半濁点 ・・－－・・長音 ・－－・－）。濁点・半濁点は直前の文字に付く（ば↔ぱ の付け替えも可。付けられなければ捨てる）。該当なしの符号は捨てる
- 入力中の符号と確定済みの文字列を大きく表示する
- **操作の符号**（文字の確定を待って判定。かなの符号とは重ならない）

| 符号          | 動作                                                                                                                                                                                                              |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SOS（・・・－－－・・・、短点3・長点3・短点3の連続9押下） | **緊急**。9つ目を離した時点で即座に緊急にする（§4.3）。判定は文字の確定とは独立した**押下の並びの履歴**で行い、押す間隔が文字の確定時間（既定 1.5 秒）を超えて文字として確定されても、直前に誤った符号が混ざっていても、末尾9押下が SOS なら緊急。履歴は、押下が 15 秒途絶える・操作の符号（・5つ・・6つ・確定）を実行する・緊急にしたとき捨てる（離れた時間の偶然の一致を防ぐ）。・5つ／・6つは無入力で確定したときだけ実行するので、SOS の先頭・末尾の・・・が食われることはない |
| ・を5つ       | モールス入力をやめてスキャンへ戻る（入力途中の文字列は残る）                                                                                                                                                      |
| ・を6つ       | 1字消す                                                                                                                                                                                                           |
| ・－・－・－  | 入力した文字列を伝達として確定し、ホーム先頭へ戻る（和文の読点「、」と同じ符号。本アプリでは読点を入力しない）                                                                                                    |

- **本人が取り残されないための保証**: モールス中は押下が符号になるためスキャンのカーソルは止まるが、(1) SOS で即緊急、(2) ・5つでスキャンへ戻る、(3) **符号の合間でなく 30 秒間無入力ならスキャンへ自動で戻る**、(4) 介助者メニュー（§6）は従来どおり使える。「止まると本人は再開できない」ため、自動復帰を省かない
- 介助者メニューを開いている間は時間の経過（文字確定・語の区切り・自動復帰）を止める。閉じるとホーム先頭からスキャンを再開する
- 入力した文字を、音声モードに応じて読み上げる（濁点・半濁点で文字が変わったときも読む）
- **注意（Bluetooth シャッター）**: 押下と解放をほぼ同時に送る機種では長押しを区別できず、・しか入力できない（SOS の緊急も出せない）。そのような機種ではモールスを使わず、スキャンを使う。介助者設定のモールスの項目にも注意書きを出す
- 振動モールスによる返答は #13 と連携して将来検討する。欧文モールスは将来

## 5. 表示

- メッセージ表示欄は常に画面上部。本人と周囲の両方から読める大きさ
- メッセージは、1 行に収まるなら改行せず、収まる最大の大きさで表示する。最小の大きさでも収まらない長文だけ折り返す（Issue #22）
- 現在のスキャン対象は、遠目でも一目で分かる強い強調（太い黄色の枠 + 面の色変化）
- 緊急は濃い赤。それ以外は緑系
- 番号キー（1-9）の表示は開発・介助者向け。既定では表示しない

## 6. 介助者操作

- 設定と緊急解除は介助者が行う
- メッセージ欄右上の**「介助者用」ボタンを通常のクリック / タップ**で開く。ボタンにフォーカスした Enter / Space でも開き、これらの操作は本人のスイッチ入力として扱わない
- 設定画面はスキャン巡回に含めない
- 「データ」タブに「設定を既定に戻す」を持つ。スキャン・入力方式・フィードバック・表示の全項目と、編集したフレーズ（全グループ）を既定値に戻す。取り込みと同じ確認（§6.1。2 回押し。1 回目は「全設定とフレーズが既定に戻る」旨を表示し、タブ切替・閉じる・欄の編集で解除）を挟み、実行後はメニューを開いたまま既定値が反映される。緊急状態（`libra:emergency`、§4.3）と本人のスキャン入力には影響しない
- 介助者メニュー表示中は本人のスイッチ入力が働かないため、以下で本人が取り残されないようにする
  - **無操作 60 秒で自動的に閉じ**、ホーム先頭からスキャンを再開する
  - メニュー表示中の **keydown**（本人が誤って触れた場合を含む）は、その押下では何も実行せず、メニューを閉じてホーム先頭から再開する。ただし、フレーズ編集の入力欄で**文字を打つ・編集するキー**（文字・Backspace・矢印・IME 変換中）は編集操作として扱い閉じない。Enter・Space（変換中以外）・Tab・音量/メディアキー・Esc は従来どおり閉じる（入力欄にフォーカスが残ったまま本人がスイッチを押しても取り残さない）。打鍵では無操作 60 秒タイマーを延ばさない
  - 例外: カテゴリタブにフォーカスがある間の **←/→/Home/End（Ctrl/Alt/Meta なし）** はタブ移動として扱い閉じない。これも打鍵なので 60 秒タイマーは延ばさない（延ばすと、タブにフォーカスが残ったまま本人が矢印スイッチを押し続けて取り残されるため）。タブのタップ（pointerdown）は従来どおり延長する。修飾キー付きは本人入力として閉じる
  - メニューパネルの**外側（背景）へのタップ**も同様に、何も実行せずメニューを閉じてホーム先頭から再開する。パネル内の操作は通常の介助者操作として扱う

### 6.1 フレーズ編集

介助者は、介助者メニューから次の画面の**伝達メッセージ項目**を追加・文言変更・削除・並べ替えできる（不快 / 不快・その他 / 痛い場所 / 要望 / 気分。要望・気分は快・要望（§4.5）の下位画面）。

- 表示ラベル（短い・20 文字まで）と伝達メッセージ（全文・100 文字まで）を別々に編集する
- **緊急・戻る・はい・いいえ・続けて・やめて・もっと・変えて・下位画面へ進む項目・痛みの強さ（§4.4.2）の位置と存在は編集できない**（§2・§4.1・§4.5）。編集内容は固定項目の位置関係を保って配置し、通常下位画面では「戻る」を先頭、「緊急」を2番目とする。ラベルが「戻る」「はい」「いいえ」「取り消し」の項目、ラベルに「緊急」（かな・全角半角・空白違いを含む）を含む項目、全文が緊急の表示（「緊急です。来てください」）と同じ項目、ラベルまたは全文が空の項目は表示に使わない（編集画面に理由を表示する）
- 1 画面の項目数（緊急・戻る・遷移項目を含む）が目安の 8 を超える場合は警告し、項目を減らすか画面を分けるよう促す（保存は妨げない。1 グループの安全上限は 20 項目）
- 画面ごとに「既定に戻す」を持つ
- 編集内容は設定と同じく localStorage（ルートキー `libra` の `phrases`）に保存する
- 設定全体（フレーズを含む）を JSON で書き出し・取り込みできる。端末の入れ替え用。書き出しには識別子（`app: "libra"`・`version`）を入れ、無い・合わない JSON、壊れた JSON は取り込まず今の設定を保つ。取り込みは確認（2 回押し）を挟み、今の設定を土台に、書き出しに含まれる検証済みの項目だけを上書きする（欠けた・範囲外の項目は今の値のまま。本人に合わせたスキャン設定が黙って既定値に戻らない）

## 7. 音

緊急警告音は鳴らさない（Issue #43）。緊急は画面上部の視覚表示と振動（§7.1）で伝える。以下は音声モード・聴覚スキャンの扱い。

| 種類           | 音声モード OFF | 効果音だけ | 短く読む   | 全部読む   |
| -------------- | -------------- | ---------- | ---------- | ---------- |
| 伝達の読み上げ | なし           | 効果音     | 短文       | 全文       |
| 聴覚スキャン   | 設定に従う     | 設定に従う | 設定に従う | 設定に従う |

### 7.1 本人への触覚フィードバック

入力の結果を、本人が他人の反応なしに知るための出力。目や耳を使いにくい人にも届くよう、振動で返す。パターンは `lib/feedback.ts` に集約し、互いに区別できる（テストで重複がないことを確認）。

| イベント                                  | 振動（標準・ms。振動・休止・振動…）                  |
| ----------------------------------------- | ---------------------------------------------------- |
| 入力受理（項目を実行した）                | 20                                                   |
| 伝達（はい・いいえ以外）                  | 40                                                   |
| はい                                      | 120（長め1回）                                       |
| いいえ                                    | 120・100・120（長め2回）                             |
| 緊急色の伝達（緊急の詳細など）            | 60・40・60                                           |
| 緊急を呼び出した                          | 300・120・300・120・300                              |
| 緊急の呼び出し中                          | 50・60・50・60・50（小さく3回）を 3 秒周期で繰り返す |
| 緊急の解除                                | 500                                                  |
| 伝達済み（介助者の応答を受信。#9 で使う） | 100・80・100・80・100・80・100                       |

- 受理の振動のあとに伝達・緊急のパターンが続くため、実際に感じるのは後のパターン（新しい振動が直前の振動を置き換える）
- 緊急の呼び出し中の周期の振動は、3 秒周期で繰り返す。**本人が入力した直後（周期の長さの間）は、周期の振動を出さない**（はい・いいえなどの振動を打ち消さない・取り違えさせないため）
- 再読み込み・再起動で緊急が復元された場合も、周期の振動を続ける（復元の直後に、緊急発生時の長い振動は出さない）。ただしブラウザは、画面に一度も触れていないページの振動を無視するため、実際に振動し始めるのは本人か介助者が一度画面に触れてから
- 振動のパターンは、標準で最低 20ms（多くの振動モーターが感じられる長さ）の振動を保つ。受理・伝達・はいは長さだけが違う単発の振動で、実機（Android）で区別できるかは確認待ち
- 介助者設定: 振動の ON/OFF（既定 ON）、強さ（弱・標準・強。振動する長さだけを 0.6 / 1 / 1.6 倍し、合間は変えない）
- **Vibration API が無い端末**（iOS Safari など）は、同じパターンを短い効果音で代替する。音声モード OFF のときに鳴らすかは設定で選べる（既定は鳴らさない）
- **振動モーターのない端末**（タブレット・デスクトップのブラウザなど。API はあっても振動しない）は、API の有無から見分けられないため、介助者設定「振動に加えて、いつも短い効果音でも知らせる」（既定 OFF）で効果音を足す
- AudioContext が使えないときは効果音を出さない。新しい効果音は直前の効果音を止めて置き換える。緊急・緊急の呼び出し中は、効果音は重ねない（振動だけ出す）
- 音声モード「効果音だけ」は、触覚フィードバックが ON のときはこの層の振動で代える（区別できるパターンを打ち消さない）。OFF のときだけ従来の短い振動を出す
- Phase 2（本人が握る外部触覚デバイス・点字セル）は調査段階であり、本書の範囲外

## 8. 限界（明記事項）

- Libra はナースコールの置き換えではない
- 本人がスイッチを押せないほど急変した場合は機能しない
- バックエンドが落ちていても、すべての伝達機能はオフラインで動かなければならない
- Bluetooth シャッターが送るキーは機種により異なり、ブラウザに届かないもの（一部の音量キー等）がある。対応機種は実機確認で確定する
