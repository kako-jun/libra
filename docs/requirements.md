# Libra — 要件仕様（正本）

この文書が Libra の最上位要件である。他の docs と食い違う場合はこの文書を優先する。

## 1. 想定利用者と前提

- 汎用品。特定の個人向けではない
- 利用者本人は**ほとんど動けない**。上下左右の選択もできない
- 本人ができる操作は、**時間で移動するカーソルが目的の項目に来たときに、スイッチを1回オンにすることだけ**（シングルスイッチ自動スキャン）
- この操作（キー/外部スイッチ）だけで、Libra のすべての伝達機能が成り立たなければならない。画面への直接のタップ（パネルの直接タップと、ボタン以外を押すこと。§3.1）は追加経路で、これに依存してはならない
- 画面を読むのは、そばにいる家族・介助者・看護師（人間）である

### 1.1 基本姿勢

- **レベル制にしない**。「できたね」など上達を促す演出・表示をしない。快/不快・はい/いいえ・定型語・スキャン・文字盤・モールス・触覚出力は段階ではなく**入口の違い**であり、使わない機能があってよい
- 最小の目的は「話せるようにする」ことではなく、**不快を伝えられる / 快を続けられる**こと
- 第一対応端末は**タブレット**（縦横両対応）。スマホでも動く
- 高価な福祉機器を前提にしない。**安価な市販デバイス**（家電量販店・100 円ショップの Bluetooth シャッター等）を前提にする

## 2. 安全の優先順位

伝達内容には命に関わる順の優先度があり、**カーソルが早く届く位置ほど優先度の高いものを置く**。

1. **緊急**
2. **はい / いいえ**
3. **快**（続けて・やめて・変えて・気分。質問への受動の答えに近い二値の入口。Issue #93）
4. **不快**（痛い・苦しい・体位など）
5. **要望**（大丈夫・ありがとう・眠りたいなど。会話寄り。Issue #93）
6. **文字盤**（自由作文。最後の手段）

Issue #93: 以前は「快・要望」を1つの入口にまとめていた（Issue #12）。「続けて・やめて・変えて」（質問への受動の答え）と「要望」「気分」（会話）は性質が違うため、「快」と「要望」に分けた。階層は増やさず、要望はホームから直接開く。

Issue #123: ホームでは、緊急の次に「もう一度」（直前の伝達をもう一度伝える。新しい内容は伝えない）を置く。聞き逃されたとき、同じ選択を最初からやり直さずに済むようにするため、緊急のすぐ次に置く。伝達が無い間も項目を消さず常設にし、出入りで はい・いいえ の位置を動かさない。はい・いいえ は、この項目のぶん 1 つ後ろになる（2 番目から 3 番目）。

自由作文を定型プリセットより前に置いてはならない。遅い経路の奥で緊急が遅れると死の危険がある。

## 3. シングルスイッチ入力

### 3.1 スイッチ

本人の入力は次の2経路だけ。1つは黄色のパネル（現在のスキャン対象）を実行する「オン」、もう1つはパネルの直接タップである。

- **キー / 外部スイッチ**: キーボードのキー押下（Space / Enter / 音量キー等を含む任意キー。キーリピートは無視）と Bluetooth シャッターボタン（OS/ブラウザに届くキー入力として受ける）。どれも同じ1つの「オン」で、**現在のスキャン対象を実行**する（§3.2）
- **タイルの直接タップ / クリック**（主ボタンのみ。右/中クリック・ペンのバレルボタンでは実行しない）: 押した**そのタイル**を、スキャン枠の位置と無関係に実行する。スキャンのカーソルは時間で動き続けており、押したタイルとは独立
- **ボタン以外を押す（Issue #134）**（主ボタンのみ）: パネル・ボタン・矢印・パンくずのリンク以外のどこを押しても、キー / 外部スイッチと同じ「オン」になり、**黄色のパネルを選ぶ**。空きマス・パネル間の隙間・伝達欄・案内欄・緊急の帯・好きな画像・戻れる伝達が無いときの矢印の場所・パンくずの現在地（リンクでない文字）も含む。パネル・ボタン・矢印・パンくずのリンクは、それ自身の操作だけをする。伝達の矢印が片側だけ出ている間は、矢印が無い側の矢印の場所（44px 四方。何も描かない）を押しても何も起きない（矢印を続けて押して端に着いた直後の押下で、黄色が選ばれないようにするため。§4.1 の履歴、Issue #129）。この押し方を切り替える設定は作らない。パネルのヒット領域はパネル要素そのものだけ。以前は背景を押しても何も起きなかった（Issue #38）

本人画面の指示文の近くに「ボタン以外を押すと、黄色を選びます」を常に出す。黄色のパネルが無いモールス画面では「ボタン以外を押すと、符号を入力します」にする。

**1回の押下で操作は1つ**。実行は pointerdown（押した瞬間。下限・離して決定の設定があれば §3.3）で行い、続いて届く click は無視して二重実行しない。押した瞬間に画面が変わると、タッチでは同じタップの click が指の下に現れた別のボタン（パンくず・矢印・「介助者用」など）へ届くため、click は押し始めた要素にだけ届け、別のボタンへは window の capture 段階で止める（そのボタンへ移ったフォーカスも外し、次のキーがそのボタンを押さないようにする）。pointerdown を伴わない支援技術の合成 click は、パネルとボタンではフォールバックとして実行し、背景では何も実行しない。介助者用メニュー表示中は黄色を選ばない（§6）。モールス画面（§4.7）では、キー / 外部スイッチの押下と、ボタン以外の押下が、同じように符号になる（緊急は SOS。モールス画面ではパネルは表示されない）。

**複数の接触（手のひら・2 本以上の指）**: 背景の押下は、ほかの指・ペン・マウスの押下が画面に残っている間は、記録だけして何もしない（モールス画面では符号にもしない）。受け付けた背景の押下が続いている間に触れたパネルも実行しない。パネルどうしの扱いと「介助者用」などのボタンは変えない。残った指がある間は次の背景の押下も数えないため、手が画面に置かれたままだと背景は反応しない（キー / 外部スイッチは効き、背景の押下が続いていなければパネルも押せる）。指を離した通知を取りこぼした接触は、同じ種類の最初の接触が始まったとき・画面のフォーカスが外れたとき・10 秒を超えたときに捨てる。そのため 10 秒を超えて置いた手の後に触れた指は数える。連打無視の下限 0.1 秒（§3.3）は、それより後に着く指や、離して決定の複数の決定を防げないので、この扱いが要る。

**背景が緊急を選ぶ具体例**: 黄色は、読み込み直後と、介助者が介助者用メニューを閉じた直後は、ホームの先頭の「緊急」にある（先頭待機の間。既定 2.0 秒）。この間に背景に触れると緊急を選ぶ。端末を持ち直す・画面を拭くなどの接触でも同じ。

**実機で確認する項目（Issue #134。未確認）**:

- click の pointerId が pointerdown と違うブラウザでも、1回の押下で操作が1つになること。備えとして、pointerId が合わない click は、位置を持つ実際の押下の click（`detail` が 1 以上）で、離してから 0.7 秒以内・25px 以内の押下があれば、その続きとみなす。この範囲を超えて届く click は防げない
- iOS Safari で、押せない場所のタップに click が出ない場合に、次のボタンの押下が止まらないこと。pointerId の無い click は、いちばん新しく離した押下のものとみなし、それより前に離した記録は捨てる。ボタンのキー操作・支援技術の click が、click の出なかった別の押下の直後（1 秒以内）に届く場合は、1 回止まることがある
- タブレットで手のひら・2 本の指が触れたとき、操作が1つになること

本人に「戻る」「上下左右」などの別入力を要求しない。

### 3.2 自動スキャン

- **起動時からスキャンが動いている**。本人が開始操作をする必要はない
- カーソルは一定間隔で次の項目へ進み、末尾の次は先頭へ戻る
- キー / 外部スイッチがオンになった（またはボタン以外を押した）時点でカーソルが乗っている項目を実行する（パネルの直接タップは押したパネルを実行する。§3.1）
- 項目を実行したら、画面遷移先の**先頭項目からスキャンを再開**する
- 伝達（メッセージ表示）が1つ完了したら、**ホーム画面の先頭（緊急）に戻る**
- **ホーム以外の通常画面（モールス画面を除く）で、入力がないままカーソルが3周したら自動でホームへ戻る**（Issue #76）。周回は「カーソルが進んだ項目数」で数える（先頭へ戻った瞬間ではなく、無入力の間に進んだ項目数が、項目数×3＝3周ぶんに達したら戻る）。画面を開いた直後（先頭から）は従来どおり3周で戻り、途中で入力したら、その時点から数え直す（入力からちょうど3周ぶん）。押している間（キー・タッチの押しっぱなし。離して決定・押下時間の下限で長押し中を含む）は数えず、離した時点から数え直す。数え直す（リセット）のは、画面遷移と本人の入力（キー / Bluetooth シャッター＝連打無視や押下時間の下限で無視された押下・長押しの繰り返しも含む、タイルのタップ、パンくず操作、介助者用メニューを開く）。画面のどこかに触れた（主ボタン以外など、何も選ばない押下を含む）ときも数え直し、触れている間は数えない（本人の手が画面に置かれたままだと自動復帰は止まる。入力を捨てないための安全側の仕様）。モールス画面と介助者用メニュー表示中（スキャン停止中）は数えず、ホームでは戻らない。戻っても緊急表示・伝達済みのメッセージ・文字盤の入力途中の文字列（文字盤を開き直すと残っている）は残る。この自動復帰の説明は画面には出さない（以前は介助者用メニュー上部の固定帯に出していたが、Issue #138 で帯ごと削除した。§4.1.2）。実測（PR #124 で再測定。本番ビルド・Chromium・390x844・スキャン間隔 0.5 秒・先頭待機は既定の 4/3 倍）は、不快（8 項目）が開いてから 12.20 秒（先頭待機 0.67 秒 + 残り 23 歩 × 0.5 秒 = 12.17 秒の計算どおり）、文字盤の行段階（14 項目。「1字消す」は 3 番目）で「1字消す」を押してから 21.25 秒（項目数 14 × 3 周 × 0.5 秒 = 21 秒）で戻る。実機のタッチ・実スイッチは未検証。
- スキャンを止める設定は本人の経路に置かない（止まると本人は再開できない）

### 3.3 誤入力対策（介助者が設定）

| 設定           | 内容                                                                  | 既定値              |
| -------------- | --------------------------------------------------------------------- | ------------------- |
| スキャン間隔   | カーソルが次へ進むまでの時間                                          | 1.5 秒（0.5〜5 秒） |
| 先頭待機       | 画面を開いた直後、先頭項目に留まる時間（間隔 × 倍率 1〜5）            | 間隔の 4/3 倍（間隔 1.5 秒で 2.0 秒） |
| 連打無視       | 直前のオンから一定時間内のオンを無視する                              | 0.5 秒（0.1〜3 秒） |
| 押下時間の下限 | この時間以上押し続けたときだけオンとみなす。押している間は進捗を表示  | 0 秒（0〜2 秒）     |
| 決定タイミング | 押した瞬間 / 離した瞬間（下限があれば、押した瞬間は下限に達した時点） | 押した瞬間          |
| 聴覚スキャン   | カーソルが進むたびに項目名を短く読み上げる                            | OFF                 |

押下時間の下限・決定タイミング・連打無視は、キー・Bluetooth シャッター・パネルの直接タップ・ボタン以外の押下のすべてで同じ判定が効く。押しっぱなし中にスキャンが進んでも、決定するのは**押し始めの対象**（キー / 外部スイッチとボタン以外の押下はカーソルが乗っていた項目＝黄色、パネルの直接タップは押したパネル）（押下中に画面が変わった、または同じ画面でも項目の並びが変わって押し始めの項目がその位置になくなった場合は、別の項目を実行せず無視する）。

先頭待機の既定は、以前の「間隔の 2 倍（3.0 秒）」から「間隔の 4/3 倍（2.0 秒）」に短くした（Issue #92。待ち時間の体感を短くするため）。範囲（倍率 1〜5）と「先頭待機 = 間隔 × 倍率」のモデルは変えない。**保存済みの設定は変えない**（倍率 2 を保存済みの端末は 3.0 秒のまま。介助者用メニュー「スキャン」タブの「初期値に戻す」（Issue #117）を押すと新しい既定になる）。範囲外の保存値（0.5・10 など）は元から無効として既定にフォールバックするため、以前は範囲外でも 3.0 秒だった端末は、更新後は新しい既定の 2.0 秒になる（想定どおり）。介助者用メニュー「スキャン」タブの倍率スライダーは 1/3 刻み（既定 4/3 を丸めずに選べる）で、「間隔 × 1.3（約2.0秒）」のように実際の秒数を併記し、倍率・スキャン間隔の変更に追従する。倍率は内部で 4/3 のまま保存・書き出す（JSON の往復で値は変わらない）。実機は未検証。

連打無視・押下時間の下限・決定タイミングの現在の動作（「押しても反応しないことがある」条件）は、設定値に追従して、原因の設定のすぐ下（介助者用メニュー「スキャン」タブの連打無視の下、押下時間の下限と決定のタイミングの下）に出す（Issue #111。以前は旧「状態」タブの「いまの動作」にまとめていた。§4.1.2「常時案内」）。先頭待機は、画面を見ればカーソルの動きで分かるため、どこにも案内を出さない（Issue #79）。

連打無視は 0 にできない（下限 0.1 秒。Issue #164。定義は `settings.ts` の `DEBOUNCE_MS_MIN`）。保存済み・取り込みの 0.1 秒未満の数値は 0.1 秒にする（数値でない値と 3 秒超は、ほかの設定と同じく取り込み前の値か既定値）。

設定は localStorage（ルートキー `libra`）に保存し、再起動後も保持する。

## 4. 画面構成と巡回順

各画面の項目は上から（スキャン順に）並べる。以下の項目名にある「→」は**下位画面へ進む項目である旨の記法**（本文書内の表記）であり、実際の画面表示は矢印文字ではなく山形アイコン＋中身の予告行で示す（DESIGN.md §2 参照）。予告は項目の途中で折り返すことがある（見える文字数を優先。「・」でだけ折り返す方式は見える文字数が平均 -1.71 文字減るため採用しなかった、Issue #82）。

### 4.1 共通規則

- ホームは「緊急」を先頭、「もう一度」（§4.2）を2番目に置く。ホーム以外の通常下位画面は「戻る」を先頭、「緊急」を2番目に置く。深い画面の途中でも緊急へ最大1周以内で届く
- 格子は**画面ごとに決まる 3 種類**で、縦横の形は画面の向き（縦長＝高さが幅以上。正方形を含む / 横長）だけで決まる。項目数・緊急中・伝達メッセージの有無・文字サイズでは変わらない（正本: docs/grid-layout.md）
  - 標準（ホームと文字盤の行段階以外の画面）: 8 セル（縦長 2列×4行 / 横長 4列×2行）
  - ホーム: 通常の 8 項目は標準と同じ 8 セル（縦長 2列×4行 / 横長 4列×2行）で空きセルを作らない。モールス入力を使う 9 項目は 10 セル（縦長 2列×5行 / 横長 5列×2行）で空き 1 マス。丸ごと空く行は作らない（Issue #127）
  - **「はい」と「いいえ」は、どの画面サイズでも同じ段で左右に隣り合う**（Issue #126）。幅の広い縦長（タブレット縦など）も 2 列で、3 列にはしない
  - 文字盤の行段階: 15 セル（縦長 3列×5行 / 横長 5列×3行。Issue #121）
  - 同じ画面の中では、全ての選択肢（緊急・戻る・通常）を同じ大きさにする。項目数でタイルの大きさを変えず、最後のタイルを引き延ばさない。項目がセル数に満たないときの余りは**空きセル**として残し、空きセルはスキャン・タップ・キー操作・読み上げの対象外とする
  - ホームが 8 項目のときの格子は下位画面と同じ。モールス使用の 9 項目のときだけ格子が違い、縦長ではホームのパネルが下位画面より低く、横長では狭い
  - 項目がセル数を超える画面（介助者がフレーズを増やした画面）だけが、固定格子でなくスクロールする別枠になる。文字盤の行段階はスクロールしない（Issue #121。以前は行段階だけがスクロールした）
- 緊急詳細は、すでに緊急状態が成立した後の詳細入力画面である。重複する「緊急」タイルは置かず、「戻る」を先頭に置く
- 緊急詳細は「戻る」の次に未選択の詳細候補を置く。ここから「戻る」を選んでも緊急状態は解除せず、親画面へ戻る
- 1画面の項目数は少なく保つ（目安 8 項目以内。ホームは 8 項目（モールス使用時は 9 項目）、文字盤の行段階は 14 項目で、9 項目のホームと文字盤の行段階は専用の格子に収める）。多い場合は2段階（グループ → 項目）にする

#### 4.1.1 画面階層の正本

以下の木が、本人画面の全 `ScreenId`、親子関係、通常の戻り先の正本である。`←` は「戻る」の遷移先を表す。`urgentDetail` と `emergencyRelease` を除く全本人画面には、現在位置から緊急状態を開始して `urgentDetail` へ移る共通分岐がある。緊急状態そのものは画面階層に属さず、どの画面へ移っても上部の専用領域に残る。

```text
本人画面
└─ home（ホーム）[先頭: 緊急 → もう一度]
   ├─ urgentDetail（緊急詳細）← home [先頭: 戻る / 緊急タイルなし。末尾: 緊急を解除]
   │  ├─ 選択後: 詳細を緊急状態へ追記して home
   │  └─ emergencyRelease（緊急を解除）← urgentDetail [戻る → 解除する。緊急タイルなし。Issue #108]
   │     └─ 「解除する」を選ぶと緊急状態を解除して home
   ├─ comfort（快）← home [先頭: 戻る → 緊急]
   │  └─ feelings（今の気持ち）← comfort [先頭: 戻る → 緊急]
   ├─ discomfort（不快）← home [先頭: 戻る → 緊急]
   │  ├─ discomfortOther（不快・その他）← discomfort [先頭: 戻る → 緊急]
   │  └─ painLocation（痛い場所）← discomfort [先頭: 戻る → 緊急]
   │     └─ painIntensity（痛みの強さ）← painLocation [先頭: 戻る → 緊急]
   ├─ requests（要望）← home [先頭: 戻る → 緊急]
   ├─ letters（文字盤・行）← home [先頭: 戻る → 緊急]
   │  └─ lettersRow（文字盤・文字）← letters [先頭: 戻る → 緊急]
```

#### 4.1.2 画面上部の情報設計

本人画面では、異なる意味の情報を同じ表示領域へ混在させない。

| 表示領域       | 表示するもの                                                                            | 表示しないもの                                     |
| -------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 緊急状態       | 未解除の主文「緊急です。来てください。」と、明示ラベル「伝えた状態:」に続く選択済み詳細 | 操作候補、通常の後続伝達、履歴を想起させる「最新」 |
| 直前の伝達     | 本人が最後に確定した通常の伝達を「直前に伝えたこと」と明示。介助者が矢印で過去の伝達を振り返れる（過去を表示している間は「過去に伝えたこと（N件前）」と明示。Issue #120） | 緊急主文、緊急詳細 |
| 現在画面の案内 | 画面の目的、ここで選ぶもの                                                              | 直前の選択結果、技術的な状態文                     |
| 現在地         | ホームから現在画面までの短いパンくず。親画面へ戻ると親までの経路へ更新する。現在地以外の祖先は押して移動できる | 選択結果、緊急状態                                 |

表示領域は、上から 緊急状態 → 直前の伝達 → 現在地・画面の案内 の順に並べる（Issue #114）。「直前に伝えたこと」は現在地や画面の案内より上位の情報なので、案内欄より上に置く（DOM の順は `.emergency-status` → `.message-panel` → `.screen-guide`）。

**伝達欄の高さと色**: 直前の伝達の枠の高さは画面の大きさで決め、内容（未伝達・短い文・長い文・過去の表示）と文字サイズ設定で変えない（例外は低い画面の高コントラストだけで、枠が太いぶんタイルの中が狭くなるので 54px でなく 51px にする。内容では変わらない）。下の案内欄とタイルは内容が変わっても動かない（Issue #131）。長い文は切らず、スクロールもさせず、折り返しと文字の大きさで全文を枠に収める。背景色は表示中の内容が持つ色で決める（Issue #135）。通常の内容は過去の表示でも最新と同じ背景、赤の内容は過去の表示でも赤にする。緊急の呼び出し・詳細の記録は赤、解除の文は通常の色。何も出していないときは通常の色。過去の表示に白い枠は付けない（Issue #130。見出しの「過去に伝えたこと（N件前）」で区別する）。緊急中の直前の伝達の色は緊急状態と一緒に保存し、再読み込みの後も同じ色で出す。

**固定の高さに収めるときの限界**: 欄の高さを固定して全文を収めるので、長い文ほど文字が小さくなる。縦長のスマホ（320x568・390x844）では、25 字前後で 16〜21px、100 字で 8.5〜10px、200 字で 6〜8px になり、100 字を超える文は離れて読めない。定型フレーズの伝達文は 100 字まで、文字盤の入力には字数の上限がない。全画面表示などの別の見せ方は持たない。本番ビルド（書体は BIZ UDGothic。#156）を Chromium で測った値（px。括弧内は行数。実機は未確認）:

直前の伝達の履歴（Issue #120）: 本人が確定した通常の伝達は、端末のメモリ内だけに最大 50 件まで持つ（古いものから捨てる。保存しないので、再読み込みすると、復元した緊急中の直前の伝達 1 件だけが残る）。直前の伝達の枠の左右には、その方向に内容があるときだけ矢印を出す（左「前の伝達を表示」＝ 1 件古い方へ、右「次の伝達を表示」＝ 1 件新しい方へ。最新では右を出さず、それより過去がなければ左を出さない。押せない状態の矢印は残さない。Issue #129）。左右の矢印の場所は常に確保し、矢印の出入りで中央の文字の位置と大きさは変わらない。片側の矢印が出ている間、反対側の矢印の場所は押しても何も起きない（§3.1）。矢印はタップ / クリックだけで押せ、スキャン対象ではない（本人のスイッチ入力に使わない）。過去を表示している間は、見出しを「過去に伝えたこと（N件前）」にする（N は最新から数えた件数）。新しい伝達・緊急・「もう一度」が起きると最新の表示に戻る（過去の表示が本人の新しい伝達を隠さないため）。起動直後や介助者が緊急を解除した直後など、最新が空のときは、見出しの文を隠して「いまは、伝えたことがありません。」を出す。枠は起動時から常に出す（Issue #131）。緊急の呼び出し・詳細も履歴に積む（§4.3）が、最新の伝達は緊急の記録ではない最後の伝達なので、緊急中にそれしか無い間も、最新には帯と同じ中身を重ねず「いまは、伝えたことがありません。」を出す（緊急の記録は左の矢印で振り返れる）。緊急中に再読み込みすると、履歴は復元した直前の伝達 1 件だけに戻り、緊急の呼び出し・詳細の記録は消える（履歴は保存しないため）。緊急そのもの（帯と詳細）は保存状態から復元され、本人が解除したときの文には復元した詳細も入るので、何の緊急だったかは解除の後も伝達欄と履歴に残る。介助者用メニューを開いている間は、背後の矢印を押しても動かない。

現在地の先頭「ホーム」には、家のアイコンを添える（Issue #113。文字と同じ色・大きさで、読み上げの対象外。文字は変わらない）。家アイコン・項目名・区切りは行ごとに上下中央を揃え（折り返した項目の区切りは最後の行の中央）、階層を移っても家アイコンは上下に動かない（Issue #128。区切りは文字ではなく同じ形の図形で、読み上げの対象外）。パンくずと、その下の画面案内文の間隔は 10px（高さ 500px 以下は 4px）にする。

現在地は `PARENT_SCREEN` と `SCREEN_TITLES` から全 `ScreenId` について導出する。痛みの強さ画面では選択済みの痛い場所、文字段階では選択済みの行を経路に反映する。現在地以外の祖先はクリック/タップでその画面へ移動できる（パンくずの文字は 16px で、押せる範囲の高さは 18.4px（16px の文字が `font: inherit` で line-height 1.15 を継ぐ）。Issue #81 以前は 12〜15px。16px にすると狭い画面の深い階層で祖先が「…」に省略されて読めなかったため、1 行に収まらないときだけ折り返し、祖先名は省略しない。実測: 320x568 の痛みの強さ・文字盤の行と 360x640 の文字盤の行だけが 2 行になり、他の画面・広い画面は 1 行のまま。列に入りきらない長い自作ラベル（介助者が最大 20 字まで編集できる）は、その項目の中で折り返し、介助者ボタンの下に潜らない。折り返しでタイルは縮む（320x568 で 1 行 -1.6px、2 行 -6.2px。長い自作ラベルではさらに縮む）が、ラベルは 13px の下限を割らない。現在地と文字盤の行ラベルは押せない。痛みの強さ画面の場所ラベルは痛い場所の選択画面へ移動）。緊急状態中でも祖先へ移動でき、緊急表示は維持される。Tab を含むほぼ全キーが本人のスイッチ入力のため、Tab でパンくずへ入る経路は作らない。フォーカスはクリック/タップ後・支援技術・プログラム focus で乗り、そこでの Enter / Space は本人のスイッチ入力にせずボタンのクリックとして扱う。「選択: …」と最後の選択を示す帯は Issue #37 で導入したが、文字が小さく現在地はパンくずと画面見出しで足りるため Issue #75 で廃止した（文字盤で選んだ文字は文字列表示 `.letter-strip` に追記される。聴覚スキャンの読み上げは帯に依存しない）。表示のための追加待機・入力は設けず、スキャンや直接入力のタイミングを変えない。

- **案内の位置づけ**: 本人（と介助者）が**画面を見て分かる**ための案内。聴覚スキャンの読み上げ対象にはしない（項目名の読み上げに長文が混ざると、スキャンのテンポを壊し、伝達の読み上げと重なる過剰読み上げになるため。領域は通常の DOM なのでスクリーンリーダーには読める）。画面を見られない利用者への事前の説明は、介助者の設定時の説明（user-guide）で担う。
- 本人が読む補助文字（「直前に伝えたこと」、パンくず、緊急詳細の「伝えた状態:」、画面案内の見出し）は、標準の文字サイズで **16px（1rem）を下限**とし、どの画面サイズでも縮めない（高さ 500px 以下・幅 480px 以下でも同じ。Issue #81。弱視の本人も使うため）。色はどのテーマ（明るい／夜間、高コントラスト ON／OFF）でも背景に対して 4.5:1 以上。「直前に伝えたこと」はメッセージ枠の文字色を継ぐ（旧 `--text-muted` は濃緑の枠の上でライト 1.44:1 だった）。文字サイズ設定（`--font-scale`）はこれらの補助文字にはまだ効かせていない（特大で最小セルのラベルが 13px 下限を割る恐れがあるため、実機を見てから別途判断）。実機（弱視の目視）は未確認。画面下の帯（`.screen-notes`、緊急中の振動の行）は別で、従来どおり 0.7rem（約 11px）を下限とし、縮めるのは高さが足りない画面（高さ 500px 以下）だけで、縦長スマホ（390x844・320x568）は基本の `clamp(0.72rem, 1.9vh, 0.95rem)` のままにする。低い画面（高さ 500px 以下）か狭い画面（幅 480px 以下）では、短縮文言に切り替える。**短縮形では理由の語（「誤作動防止」「呼び出し継続の合図」など）を省くことがあるが、操作に関わる事実（何が起きるか・何をしても反応しない条件。短押しは数えない、押した瞬間は決まらない、読み上げは直後の1項目分だけ割り込まれずその後は切れることがある、等）は省かない**。行数・条件・順序は変えない（該当すれば必ず出る）。
- モールス画面も本人画面と同じで、固定領域には緊急中の振動まわりだけが出る（通常時は何も出ない）。モールス固有の操作・自動挙動（長押しの境目・下限未満の無視・文字確定・語区切り・自動復帰・SOS 等）は §4.7 の凡例（`.morse-legend`）に全項目を出す。凡例は「この画面の操作候補」（スキャン画面のタイルに相当する、本人が使う操作の一覧）であり、画面下の固定領域は「画面を問わず効く自動挙動の注記」なので役割を分け、凡例は固定領域へ移さない（DESIGN.md §9）
- 本人画面の下端の領域は、出ているとき（緊急中）も、狭幅・横向きでも本人画面（タイル・メッセージ・スキャン枠）が画面内に収まる（格子がスクロールせず埋まる）よう高さを抑える（DESIGN.md §10・実測表）。通常時は帯がないぶん、格子が高くなる
- 画面は常に見えている画面ぴったり1画面で、ドキュメントはスクロールしない（`html, body` は `overflow: hidden`、`body` は `position: fixed; inset: 0`。`100vh` 基準の高さは `html/body` に置かず、`#app` → `.app-shell` は `height: 100%`（body 基準）で受ける。`min-width` も置かないので幅 320px 未満の端末でも右が切れない。スマホのブラウザは 100vh がアドレスバーを隠した大きな高さで、見える高さより長いドキュメントができ、ドラッグでヘッダが見切れフッタが浮くため。Issue #84）。内部スクロールは、セル数を超えた画面の格子・介助者用メニューのタブ内容・メッセージ欄だけ（文字盤の行段階は Issue #121 で格子に収めたのでスクロールしない）。Chromium では旧実装でも不具合が再現しないため、実機（iOS Safari／Android Chrome）での確認は未了
- 案内に入れていない自動挙動（理由）: 先頭待機（画面を見れば分かる。Issue #79）／ キーの自動リピートは無視する（押しっぱなしで繰り返し実行しない。利用者の想定どおりで、画面に出す価値より行数の損が大きい）／メニューは開くたびに「使用準備」タブから始まる（開いた直後に見える）／セル数を超えて格子がスクロールするとき、スキャン中のタイルへ自動でスクロールする（見た目の追従で操作が変わらない）
- 開発用の数字キー（?dev）は対象外

介助者用メニューは、中央のポップアップではなく画面全体の設定画面（高さ固定。暗幕・角丸・影なし。内容が長いときはタブの中身だけが内部スクロールし、ヘッダ・タブ列は固定なので、タブを切り替えても外枠の大きさと位置は変わらない。Issue #68）で、閉じる（カテゴリ切替と独立して常に見える常設の行。どの画面幅でも右上の角に固定。Issue #91）と、緊急中だけ出る緊急を解除（緊急が無いときはボタンごと出さない。Issue #137。左右の中央に置き、幅に余裕があれば閉じると同じ行、狭い幅では 2 行目。Issue #152。DOM 順＝Tab 順は 緊急解除 → 閉じる。実機未検証）と、全画面幅の上部カテゴリタブ（スマホは横スクロール、広い画面は均等配置。同一 DOM。タブ列が横に続くときは、続きがある側にだけ矢印「前のタブを表示」「次のタブを表示」を出し、タップで表示範囲を動かす。Issue #111）、選択中カテゴリの設定だけを表示する設定ペインで構成する。タブは ARIA tablist/tab/tabpanel で、タブにフォーカスがあるときの ←/→/Home/End（修飾キーなし）だけがタブ移動に使え（打鍵なので無操作 60 秒タイマーは延ばさない）、Enter/Space を含む他のキーは従来どおり本人のスイッチ入力として扱いメニューを閉じる（§6）。タブの並びは、重要なものほど左で、関係の近いものを隣にする: 使用準備 / スキャン / 音と振動 / 表示 / フレーズ / モールス / データ / このアプリ（Issue #140・#157。矢印キーの移動順もこの順）。メニューを開くたびに「使用準備」から始める。本人向けの画面案内・スキャン対象・`ScreenId` からは分離する。ヘッダーとタブの間に固定の説明は置かない（Issue #138）。設定に応じた現在の動作（連打無視・押し方・読み上げの割り込み）は、各設定のすぐ下に出す（上の「常時案内」。Issue #111）。タブの中身の構成は §4.1.1 の木と §6 のとおり。介助者用メニューは一般的なアプリの文字にする（Issue #163）: 本文は 16px の通常の太さ、見出し（「介助者用メニュー」は 20px、「このアプリ」の「使い方」）だけを太くする。ほかに太くするのは、色だけに頼らないための選択中タブと、状態の印（✓ / !）だけ。入力欄は 16px 以上、押せる範囲は 44px 以上（1 行のチェックボックスのラベルも 44px）。本人画面と文字サイズの見本は変えない。「使用準備」の状態の表示は枠・角丸を持たない（操作できるボタンに見せない。Issue #111）。左の線も引かず、完了と注意は印（✓ / !）と文で区別し、対応が必要な表示には背景を付ける（ほかの注意の表示も左の線を引かない。Issue #142）。

#### 4.1.3 表記規則: 本文と短いラベルの句読点（Issue #46）

画面に出す文言は、**文として読むもの（本文）** と **短いラベル** に分け、句読点を揃える。

| 種別                         | 句読点                                                                                 | 対象                                                                                                                                                                                                                                                                                               |
| ---------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本文                         | 文末に全角の句点「。」、文中の区切りは読点「、」                                       | 上部メッセージ欄の伝達文・状態文（「直前に伝えたこと」の既定文含む）、緊急の主文、画面の案内（`SCREEN_GUIDANCE`・痛みの強さの案内）、常時案内（`.screen-notes` の各行と、設定の下の動作の説明の各行、短縮形も同じ）、介助者向けの注意書き・操作結果の文、モールス画面の凡例、編集可能フレーズの既定の伝達文 |
| 短いラベル                   | 付けない                                                                               | ボタン・タイル・タブ・メニュー項目のラベル、見出し・小見出し（「直前に伝えたこと」「伝えた状態:」「介助者用メニュー」等）、設定項目名・チェックボックスの説明つきラベル、現在地（パンくず）、緊急詳細の選択済みラベル、aria-label                                                           |
| 「項目名: 値」形式の状態表示 | 値が語のとき付けない（「オフライン準備: 完了」）。値が指示の文を含むときは文末に付ける | 動作状態（画面スリープ防止・オフライン準備）                                                                                                                                                                                                                                                       |

- 伝達文は、タイルのラベルと別の文であることを句点で示す（タイル「はい」→ 上部に「はい。」、タイル「苦しい」→「苦しいです。」）。はい・いいえ・ありがとうのような短い返答・挨拶の伝達文も、本文なので句点を付ける。
- 疑問形は「？」（全角）で終え、「。」を重ねない。体言止め・感動詞の本文も、文として読ませるなら句点で終える。現行の既定文に疑問形はない。
- 句点の後に（　）や「　」が続く文は、句点を括弧の外に置く（「…（とても）。」）。括弧内に完結した文を入れるときだけ括弧内に句点を置く。
- 記号は全角の「。」「、」「？」、省略は「…」（3点リーダ1文字）に統一し、半角の「.」「,」「...」を日本語文に混ぜない。コロンは見出しの区切りとして半角「:」を使う（本文の終端には使わない）。
- 例外: 文字盤・モールスで本人が組んだ文字列は、本人の入力そのものなので句点を足さない（加工しない）。画面遷移タイルの中身の予告（「あ行・か行・さ行・た行・な行・は行…」「続けて・やめて・変えて・要望・気分」）はラベルの一部なので句点を付けない。
- 読み上げ（`speechSynthesis`）には本文をそのまま渡す。句点で短い間が入るのは許容する。ラベルは句点なしのまま読む（スキャンの項目名の読み上げは変わらない）。
- 緊急の主文の正本は `frontend/src/lib/phrases.ts` の `EMERGENCY_MESSAGE`（「緊急です。来てください。」）。App.tsx は同じ値を import する。
- 符号・記号で終わる行（モールス凡例の符号など）も、符号の直後に句点を置かない。符号は括弧で囲み（例:「短く押す＝短点（・）、0.5秒以上押す＝長点（－）。」）、句点は括弧の外に置いて、符号の一部に見えないようにする。
- 保存済みフレーズ（localStorage の `phrases`）と取り込み JSON は、**一度だけ**昇格する。設定に移行済みの印 `phrasesVersion`（現行 1）を持たせ、印が無い・古い保存値と、印が無い・古い取り込み JSON だけを、同じグループ・同じ id の既定と**句点を除いて完全一致する文だけ**新しい既定（句点つき）へ揃える（句点導入前に既定のまま保存されたものの救済。`normalizeSettings` が印を見て昇格し、印を付ける）。印が現行以上の保存値・取り込みは一切書き換えない（介助者が既定 id の文から句点を意図的に消して保存しても、次の起動で戻らない）。介助者が書き換えた文は、印が無くても触らない。印は保存・書き出し（`phrasesVersion`）に含め、新規保存・編集・「フレーズ」タブの初期値に戻す・往復（書き出し→取り込み）で保たれる。「緊急の表示と同じ文」「予約ラベル」の判定は句読点・「…」「・」・空白を除いて比べる。

### 4.2 ホーム

1. 緊急
2. もう一度（Issue #123）
3. はい
4. いいえ
5. 快 →
6. 不快 →
7. 要望 →
8. 文字盤 →
9. （介助者が設定でONにしたときだけ）モールス →（§4.7）

「もう一度」は常設で、位置を動かさない。直前の伝達があるとき（または緊急中のとき）に選ぶと、次の順で直前の伝達をもう一度伝え、ホームへ戻る。新しい伝達ではないので、履歴は変えない。

- 直前の伝達があるとき: そのときの振動パターン（はい・いいえ・通常）を出し直し、読み上げる（音声モードに従う）。伝達欄の見出しは「直前に伝えたこと（もう一度）」になり、枠を点滅させて、音声が無くても周囲に分かるようにする（端末の「視差効果を減らす／動きを減らす」設定（prefers-reduced-motion）では点滅させず、黄色の枠を止めたまま出し、続けて押したときも分かるよう、回数の偶奇で枠の太さを 6px / 10px と変える。緊急の帯も同じ）。次の伝達などで元の見出しに戻る。押せない（伝えるものが無い）「もう一度」は、受け付けの軽い振動も出さない
- 直前の伝達が無く緊急中のとき: 緊急の呼び出し（振動と読み上げ）をもう一度伝え、緊急の帯を点滅させる
- どちらも無いとき: 伝え直すものが無いので、押しても何も伝えない。項目は消さず、薄く表示して（`.tile-unavailable`、`aria-disabled="true"`）、押せないことを示す

優先順位（緊急 → もう一度 → はい／いいえ → …）を構造で守るため、設定で増える項目（モールス）は「はい」「いいえ」より後ろにだけ置く。「はい」と「いいえ」は、どの画面サイズでも同じ段で左右に隣り合う（Issue #126）。

並びは 快 → 不快 → 要望（Issue #93）。はい／いいえに近い二値の答え（快）を先に、会話寄りの要望を後ろに置く。

項目数: 通常 8（モールスOFF）、モールスON で 9。8 項目は 8 セル（縦長 2列×4行 / 横長 4列×2行）で空きセルが無く、9 項目は 10 セル（縦長 2列×5行 / 横長 5列×2行）で空き 1 マス（§4.1。Issue #127）。項目数は介助者の設定だけで決まり、本人の操作・伝達・緊急では変わらない。モールスは最後尾（最低優先）。

### 4.3 緊急

- 選択した瞬間に「緊急です。来てください。」を赤で大きく表示する。**緊急警告音は鳴らさない**（周期音が #32 の「コンコン」の一因と疑われるため(病院を連想させる不快さも含む)。Issue #43）
- 誤報の害より見逃しの害が大きいため、**確認手順を挟まない**
- モールス入力（§4.7）中は、SOS（・・・－－－・・・、短点3・長点3・短点3の連続9押下）を**休まず続けて**打つと緊急になる。確定を待たず9つ目を離した時点で即座に緊急にする
- 表示後、任意で詳細（苦しい / 痛い / 息ができない / 吐きそう / 胸が痛い）を追加できる
- 緊急詳細の候補には、すでに成立している状態と重複する「緊急」タイルを置かない。選択済み詳細は候補欄へ重ねず、上部の緊急状態領域に「伝えた状態:」として表示する
- 緊急中の後続伝達は、曖昧な「最新」表示や履歴として緊急主文へ混ぜず、「直前に伝えたこと」領域へ1件だけ表示する
- **緊急表示は、介助者が解除するか、本人が 緊急 → 緊急を解除 → 解除する を選ぶまで残る**（Issue #108）。それ以外の本人入力（はい・いいえ・もう一度・ほかの項目など）では、上書きも解除もされない
- 緊急は、解除されるまで画面上部の静かな視覚表示で残る。音は出さない（振動は §7.1 のとおり）
- **本人による解除（Issue #108）**: 緊急詳細（`urgentDetail`）の末尾に、確認画面へ進む項目「緊急を解除」を置く。この項目では解除しない。確認画面 `emergencyRelease` は「戻る → 解除する」の 2 項目で、先頭は「戻る」なので、続けて入力しても解除にならない。「解除する」を選んだときだけ解除する（誤操作で緊急が消えないようにする）。確認画面でも、無入力のままカーソルが 3 周する（§3.2）とホームへ戻る。このとき緊急は解除されず、残る
- 解除すると、緊急の帯・保存状態（`libra:emergency`）・周期の振動が止まる（介助者の解除と同じ処理）。解除したことは、振動（500ms の 1 回。§7.1）と、伝達欄の解除の文の表示と読み上げ（音声モードに従う）で、本人と周囲に知らせる。解除の文には選んだ詳細を選んだ順に入れる（例「緊急（息ができない・痛い）を解除しました。」。詳細が無ければ「緊急を解除しました。」）。緊急の呼び出し（「緊急です。来てください。」）と各詳細（「緊急です。来てください。息ができない」）も伝達の履歴（§4.1）に積むので、帯が消えた後に来た介助者も、矢印で何の緊急だったかを振り返れる（同じ詳細・緊急の再選択は二重に積まない）。解除を元に戻す操作は無く、緊急にしたいときは緊急を選び直す
- **再読み込み・再起動後も、解除まで復元される**（緊急状態を localStorage の `libra:emergency` に保存。有効期限なし）。復元時は視覚表示を再開する。警告音は無いので、自動再生制限に関する案内表示も出さない

戻る / 緊急 / 痛い →（場所: 頭・胸・おなか・背中腰・手足・その他）/ 苦しい / 痰を取ってほしい / 体の向きを変えたい / トイレ / その他 →

#### 4.4.1 不快・その他

戻る / 緊急 / 暑い / 寒い / 喉が渇いた / かゆい / 眠れない

#### 4.4.2 痛みの強さ

痛い場所を選ぶと、**強さの画面**へ進む（場所を選んだだけでは伝達しない）。

戻る / 緊急 / 場所だけ / 少し / かなり / とても

- 「場所だけ」を先頭に置く（強さを選べない・選びたくない場合も最短で伝えられる）。伝達文は場所だけ（例:「胸が痛いです。」）
- 少し / かなり / とても は、場所の全文の「痛いです」の前に強さを入れる（例: 不快 → 痛い → 胸 → とても =「胸がとても痛いです。」）。「痛いです」を含まない（介助者が編集した）全文は、句点で終わるなら句点の前に、終わらないなら末尾に（とても）を足す（「その他の場所が変です。」→「その他の場所が変です（とても）。」）
- 「とても」は緊急色（urgent トーン）。場所の色（胸=緊急色）は場所だけ・少し・かなりに引き継ぐ。緊急の警告音は鳴らさない（緊急は §4.3 の別経路）
- 6 項目で 8 項目以内を保つ

### 4.5 快と要望

Issue #12 で導入した「快・要望」を、Issue #93 で「快」（本節 4.5.1）と「要望」（4.5.2、ホーム直下）に分けた。

#### 4.5.1 快

戻る / 緊急 / 続けて / やめて / 変えて / 気分 →

- **二値の入口**「続けて・やめて・変えて」を最上位に置く（「もっと」は「続けて」と意味が同じため置かない。本人は今の刺激や行為への好み・拒否を、これだけで伝えられる）。伝達文は「続けてください。」「やめてください。」「変えてください。」。はい・いいえと同じく**編集できない固定項目**
- **気分**（不安 / さみしい / 落ち着かない）を「気分 →」に置く。**独立の入口にしなかった理由**: ホームは項目が多く（§4.2）、不快の画面（8 項目）にも入らないため、快の中に置いた。気分も不快側の内容を含むが、身体の不快（§4.4）より優先度は低いと位置づける
- 快の最上位（続けて/やめて/変えて と「気分」への遷移）は編集できない。気分は介助者がフレーズ編集（§6.1）で追加・変更・並べ替えできる
- 要望の入口は快の中に置かない（Issue #93。以前は「要望 →」が快・要望の中にあった）

#### 4.5.2 要望

戻る / 緊急 / 大丈夫 / ありがとう / 眠りたい / 静かにしてほしい / 家族に会いたい / 話したい

- ホームの「要望 →」から直接開く（階層を増やさない。Issue #93）。通常下位画面の固定項目は §4.1 の戻る・緊急
- 介助者がフレーズ編集（§6.1）で追加・変更・並べ替えできる。テレビ・音楽もここに追加できる
- **保存キー名**: 要望のフレーズは保存データ（localStorage / 書き出し JSON）の `phrases.moodRequest` に入る。Issue #93 で画面ID `moodRequest` は `comfort`（快）に改名したが、保存済みの設定を壊さないため、**保存キー名 `moodRequest` は変えない**（画面ID `requests` のフレーズグループ）

### 4.6 文字盤

- 文字は**清音 46 字 + 長音「ー」**。濁点・半濁点・小書き文字は置かない（読むのは人間であり、「めかね」→「めがね」は文脈で補える。入力ステップを増やさないことを優先する）
- **2段階スキャン**
  - 行段階: 戻る / 緊急 / 1字消す / あ行 / か行 / さ行 / た行 / な行 / は行 / ま行 / や行 / ら行 / わ行 / 確定（14 項目。Issue #95 で末尾の「はい・いいえ →」と `lettersYesNo` 画面を廃止した。はい・いいえはホームの 3・4 番目にあり、文字盤の中に同じ答えへの経路を持たない。入力途中の文字列はホームへ戻って答えても残る。Issue #121 で「1字消す」を末尾から緊急の次へ移した。見つけやすくするため）。専用の 15 セル固定格子（縦長 3列×5行 / 横長 5列×3行。§4.1）に全項目を収め、スクロールしない
  - 文字段階: 戻る（行段階へ）/ 緊急 / その行の文字（わ行は わ・を・ん・ー）
- 入力途中の文字列は常に画面上部に大きく表示する。そばの人が先読みして「○○？」と聞き、本人は「はい / いいえ」で答える運用を前提にする（答えはホームの「はい」「いいえ」で伝える。文字盤の中には置かない、Issue #95）
- 「確定」で入力文字列をメッセージとして表示し、ホーム先頭へ戻る

### 4.7 モールス入力（上級者向けの逃げ道）

単一スイッチのモールス入力に慣れた人のための、文字盤より速い入力。学習負荷が高いため**既定導線にはしない**。介助者が設定で ON にしたときだけ、ホームの**最後**（文字盤の後ろ）に「モールス」が出る。

- **入力**: キー / 外部スイッチか、画面のボタン以外の場所を押す（Issue #134）。短押し＝短点（・）、長押し＝長点（－）。長押しの境目は介助者設定（既定 0.5 秒、0.15〜1.5 秒）。押している間は、その時点で・と－のどちらになるかを表示する。#6 の押下時間の下限は雑音除去として効き（それに満たない押下は符号にしない）、長押しの境目はその下限より長くなる。連打無視（§3.3）はモールス中は適用しない（短点の連続入力を妨げないため）
- **文字の確定**: 最後にスイッチを**離してから**一定時間（既定 1.5 秒、0.5〜3 秒）無入力で、入力中の符号を1文字として確定する。**押している間は、文字の確定も語の区切りも無操作での復帰も進めない**（ゆっくり長押しする人の SOS の緊急が、押している最中の確定でばらけないため）。解放を取りこぼして 10 秒以上押しっぱなしになった入力は、符号にせず捨てる
- **案内は常に画面に出す（暗黙の操作を作らない）**: モールス画面には、短押し＝短点（・）／長押し＝長点（－）（境目の秒数。符号の直後に句点を置かない。§4.1.3）、緊急＝SOS（・・・ －－－ ・・・。休まず続けて打つと待たずにすぐ。文字の確定時間休むと数え直し）、・を5つ→待つとスキャンへ戻る、・を6つ→待つと1字消す、・－・－・－→待つと確定して伝える（操作の符号は文字の確定を待って実行され、SOS だけが休まず続けて打てば待たずに即緊急になることを明記する。SOS の数え直しの秒数は文字の確定時間と同じ）に加えて、時間で自動で起きること（文字の確定までの秒数・語の区切りまでの秒数・何も押さないとスキャンへ戻る秒数・10 秒を超えて押しっぱなしの入力を無効にすること）を常時表示する。押下時間の下限（#6）が設定されているときだけ「◯秒未満の押下は数えない」を1行足す。押したら出る・設定で隠す・初回のみ、にはしない。秒数は介助者設定の値に追従する。本人はスイッチだけでスクロールできないため、**全項目がスクロールなしで画面内に収まる**こと（390×844・568×320・844×390・320×568 で確認）。収めるため、モールス画面では画面名の階層表示・直前に伝えたことの枠を隠し、案内の文字・余白・列数を画面サイズに合わせて詰める（レイアウトの数値は DESIGN.md §9）
- **語の区切り**: さらに無入力が続く（既定 4 秒、1.5〜8 秒。文字の確定より 0.5 秒以上長いことを保存値で保証する）と、全角空白を入れる（分かち書き）。1字消した後・該当なしの符号を捨てた後・画面に入り直した直後は、次の入力があるまで入れない
- **符号は和文モールス**（かな・濁点 ・・・半濁点 ・・－－・・長音 ・－－・－）。濁点・半濁点は直前の文字に付く（ば↔ぱ の付け替えも可。付けられなければ捨てる）。該当なしの符号は捨てる
- 入力中の符号と確定済みの文字列を大きく表示する
- **緊急と操作の符号**（SOS だけは確定を待たず即座に実行する。かな・操作の符号とは重ならない）

| 符号                      | 動作                                                                                                                           |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| SOS（・・・－－－・・・） | **緊急**（確定を待たず即座）。休まず続けて打つと、9つ目を離した時点で即座に緊急にする（§4.3）。詳細は下の「緊急（SOS）の判定」 |
| ・を5つ                   | （確定を待って）モールス入力をやめてスキャンへ戻る（入力途中の文字列は残る）                                                   |
| ・を6つ                   | （確定を待って）1字消す                                                                                                        |
| ・－・－・－              | （確定を待って）入力した文字列を伝達として確定し、ホーム先頭へ戻る（和文の読点「、」と同じ符号。本アプリでは読点を入力しない） |

- **緊急（SOS）の判定**:
  - 休まず続けて入力中の（確定前の）**1つの符号の末尾**が `...---...` なら、その押下を離した時点で即緊急にする（確定を待たない）。入力中の符号は緊急で捨てるだけで、確定済みの文字列は変わらない
  - 前に誤符号があっても、休まず続けて打てば緊急になる（確定前の符号が6押下を超えると、どのかな（最長5押下）・操作の符号（最長6押下）にもなりえないため）。誤符号を休んで確定したあとの SOS でも緊急になる
  - **休み（文字の確定時間。既定 1.5 秒）を挟んで確定した文字をまたぐ並びは数えない**。文字ごとに休んで打った SOS は緊急にならず、休むと数え直しになる。かな複数字の符号の連結が偶然 SOS の配列になる語（かぜ・かぜぐすり・おそく・くよくよ・られぬ 等）で誤って緊急にならないための仕様
  - ・5つ／・6つは無入力で確定したときだけ実行するので、SOS の先頭・末尾の・・・が食われることはない
- **本人が取り残されないための保証**: モールス中は押下が符号になるためスキャンのカーソルは止まるが、(1) SOS で即緊急、(2) ・5つでスキャンへ戻る、(3) **符号の合間でなく 30 秒間無入力ならスキャンへ自動で戻る**、(4) 介助者用メニュー（§6）は従来どおり使える。「止まると本人は再開できない」ため、自動復帰を省かない
- 介助者用メニューを開いている間は時間の経過（文字確定・語の区切り・自動復帰）を止める。閉じるとホーム先頭からスキャンを再開する
- 入力した文字を、音声モードに応じて読み上げる（濁点・半濁点で文字が変わったときも読む）
- **注意（Bluetooth シャッター）**: 押下と解放をほぼ同時に送る機種では長押しを区別できず、・しか入力できない（SOS の緊急も出せない）。そのような機種ではモールスを使わず、スキャンを使う。介助者設定のモールスの項目にも注意書きを出す
- 振動モールスによる返答は #13 と連携して将来検討する。欧文モールスは将来

## 5. 表示

- メッセージ表示欄は常に画面上部。本人と周囲の両方から読める大きさ
- メッセージは、1 行に収まるなら改行せず、収まる最大の大きさで表示する。最小の大きさでも 1 行に収まらない長文は折り返し、高さが固定の枠に全文が収まる最大の大きさにする（Issue #22、#131）
- 現在のスキャン対象は、遠目でも一目で分かる強い強調（暗い面への反転 + 太い黄色の枠一本。白縁・二重枠なし。kako-jun 確定 2026-10-07: 明るいテーマで黄枠単独は白に 1.53:1 で WCAG 1.4.11 に適合しないため、暗い面への反転で 10.63:1 を確保する）
- 赤は上部メッセージ領域（緊急状態帯・緊急色調のメッセージ）だけ。パネルは真っ赤にせず緑系を基本にする。緊急入口パネルは色や面では装飾せず（Issue #36）、ラベル「緊急」・固定位置・上部の緊急状態帯の文言で区別する。アイコンは全項目共通の様式であり、緊急だけの装飾ではない（次項）
- **押すと伝達欄が赤くなるパネル（Issue #136）**: このパネルだけ、面を赤みのある専用の色にする（ライト `#ffe3e3`・文字は他のパネルと同じ濃い色。夜間 `#663f2a`・文字は白系）。パネルの色と伝達欄の色は同じ tone の指定から決め、食い違わせない。既定のフレーズでは「苦しい」、どの痛い場所でも「とても」、「胸」を選んだ後の「場所だけ・少し・かなり・とても」。利用者が追加した・取り込んだフレーズも同じ規則に従う。画面遷移だけのパネル（「胸」など）・緊急パネル・緊急の詳細（選んだときに赤くなるのは緊急の帯。伝達欄が赤になるのは、過去の記録を表示するときだけ。#135）は対象外。現在位置の色と黄色の枠は変えない。同じ色のパネルが隣り合っても区切り線が見える
- **タイルのアイコン（Issue #115）**: ホームの全項目（緊急・もう一度・はい・いいえ・快・不快・要望・文字盤・モールス）と、下位画面の「戻る」には、意味の分かる線画のアイコン（`TileIcon.tsx`）をラベルに添える。介助者が編集できるフレーズ項目には付けない。色は文字と同じ（`currentColor`。赤くしない）。ラベルの文字・aria-label・読み上げは変えず、アイコンは読み上げ・スキャン順の対象外（`aria-hidden`）。セルの高さに余裕があるとき（コンテナクエリ `min-height: 150px`）はラベルの上に大きく（文字の 1.9 倍。ホームで下の予告まで入りきらないパネルでは、文字を小さくせずアイコンを縮め、文字・予告と重ねない。Issue #127）、足りない低いセルではラベルと同じ行の左に文字と同じ高さで置く。ホームは「アイコン + 4 文字」が 1 行に入る大きさをラベルの上限にする（`--label-fit-chars` 5.3。ほかの画面は 4.02）
- **好きな画像（Issue #122）**: 介助者が、本人の好きな画像を 1 枚だけ設定できる。本人画面の案内欄の「介助者用」ボタンの左に出す（縦横比を保ち、切り抜かない。低い画面・狭い画面では小さくして格子を優先する）。画像はボタンではないので、押すと背景と同じく黄色のパネルを選ぶ（§3.1）。設定は介助者用メニュー「表示」タブの「画像を選ぶ / 画像を変える / 画像を消す」。保存先は localStorage のキー `libra:photo`（data URL）で、端末の中だけに置き、外部へは送らない。保存の前に長辺 480px に縮小する（拡大はしない。WebP。WebP を書き出せないブラウザで大きすぎるときは白地の JPEG にする）。上限（PHOTO_MAX_CHARS）は 300,000 文字（約 220KB）。長辺 480px の WebP は写真でもおよそ 3〜12 万文字なので余裕を見た値で、超えるときは白地の JPEG（品質 0.85、それでも超えれば 0.6）にし、それでも超える画像は保存しない（「保存できませんでした。もっと小さい画像を選んでください。」）。読み込みは長さを問わないので、以前の上限（1,500,000 文字）で保存した画像もそのまま表示できる。設定（ルートキー `libra`）とは別のキーで、設定の書き出し・取り込みには含めない（画像は大きく、端末の入れ替え用 JSON を貼り付けで扱えなくなるため）。「表示」タブの「初期値に戻す」で消える
- 肯定・穏やかのトーンは持たない（Issue #77）。「はい」「続けて」が肯定かどうかは介助者が口頭で聞いた質問の文脈で決まり、アプリが意味を決めつけない。そのほかのパネルは同じ通常面で（上の「押すと伝達欄が赤くなるパネル」を除く）、トーンは通常と緊急のみ。保存済み設定・書き出し JSON の `positive`／`calm` は読み込み時に通常へ読み替える（保存済みの旧値は、次に設定を保存するまで残るが、読み込み時に常に通常へ正規化される）。「はい」「いいえ」の読み上げ・振動の区別は `id` で行い、トーンに依存しない
- 番号キー（1-9）の表示は開発・介助者向け。既定では表示しない

## 6. 介助者操作

- 設定は介助者が行う。緊急の解除は、介助者に加えて本人もできる（本人は 緊急 → 緊急を解除 → 解除する。§4.3）
- 画面上部の案内欄（現在地・画面の案内）の右上にある**「介助者用」ボタンを通常のクリック / タップ**で開く（開く対象の名称は「介助者用メニュー」。ボタンの aria-label は「介助者用メニューを開く」）。ボタンにフォーカスした Enter / Space でも開き、これらの操作は本人のスイッチ入力として扱わない
- 「介助者用」ボタンの見た目（Issue #109）: メニュー内の「閉じる」と同じ面・文字色・角丸（濃い緑の面 `--caregiver-close-bg`・白文字 `--caregiver-action-text`・角丸 8px・余白 10px 14px）にして、開く・閉じるを同じ位置・同じ形のボタンにする。本人画面の「介助者用」ボタンは太字・1.125rem のまま。メニュー内の「閉じる」の文字は 16px の通常の太さで、文字の大きさと太さは一致させない（Issue #163）。案内欄の高さいっぱいに伸ばし、案内欄の上・右・下の余白を同じ値（`--guide-pad`。標準 10px、狭い・低い画面 4px、モールス画面の低い画面 3px）にそろえる。専用の色トークン `--caregiver-button-bg` / `--caregiver-button-text` は廃止した
- タップで開いた直後に、同じタップの click でメニューが閉じてしまう不具合があった（Issue #112。タッチでは、開いた直後のメニューの右上の「閉じる」が「介助者用」ボタンと同じ位置にあり、同じタップの click が「閉じる」へ届いていた）。click は押し始めた要素にだけ届け、同じタップの click が別のボタン（開いた直後の「閉じる」）へ届くときは、window の capture 段階で止める（§3.1 の「1回の押下で操作は1つ」と同じ仕組み。Issue #134）
- 設定画面はスキャン巡回に含めない
- **初期値に戻す（Issue #117）**: 「設定全体を既定に戻す」（以前は「データ」タブ）は廃止し、「スキャン」「モールス」「音と振動」「表示」「フレーズ」の各タブの末尾に「「<タブ名>」タブの設定を初期値に戻す」を持つ。戻す対象は、そのタブの設定だけ（正本: `frontend/src/lib/settings.ts` の `SETTINGS_SECTION_KEYS`。スキャン＝間隔・先頭待機の倍率・連打無視・押下時間の下限・決定のタイミング・聴覚スキャン / モールス＝使うかどうか・長押しの境目・文字の確定・語の区切り / 音と振動＝音声モード・振動の ON/OFF と強さ・効果音の 2 設定 / 表示＝文字サイズ・明るさ・高コントラスト（と好きな画像。§5）/ フレーズ＝全グループのフレーズ）。ほかのタブの設定は変わらない。2 回押しで実行する: 1 回目は、どのタブの何が戻るかを表示し、ボタンが「もう一度押すと初期値に戻す」に変わって「やめる」が出る。2 回目で実行し、「やめる」・タブの切替・メニューを閉じるで確認の状態は解除される。実行後はメニューを開いたまま既定値が反映される。緊急状態（`libra:emergency`、§4.3）と本人のスキャン入力には影響しない
- **タブの中身の整理（Issue #111・#116・#119）**:

  - メニューは画面全体のパネルで外側（背景）が存在しないため、タップで閉じる経路はない。パネル内の操作は通常の介助者操作として扱う。メニュー表示中は、どこを押しても黄色のパネルを選ばない。メニューを閉じた押下の click は、背後のパネル・ボタンへ届けても何も実行しない。ボタン以外を押したままメニューを開いた場合、その押下は取り消す

### 6.1 フレーズ編集

介助者は、介助者用メニューから次の画面の**伝達メッセージ項目**を追加・文言変更・削除・並べ替えできる（不快 / 不快・その他 / 痛い場所 / 要望 / 気分。要望はホーム直下、気分は快（§4.5）の下位画面。Issue #93）。

- 表示ラベル（短い・20 文字まで）と伝達メッセージ（全文・100 文字まで）を別々に編集する
- **緊急・戻る・はい・いいえ・続けて・やめて・変えて・下位画面へ進む項目・痛みの強さ（§4.4.2）の位置と存在は編集できない**（§2・§4.1・§4.5）。編集内容は固定項目の位置関係を保って配置し、通常下位画面では「戻る」を先頭、「緊急」を2番目とする。ラベルが「戻る」「はい」「いいえ」の項目、ラベルに「緊急」（かな・全角半角・空白違いを含む）を含む項目、全文が緊急の表示（「緊急です。来てください。」。句読点・空白の違いは無視して比べる）と同じ項目、ラベルまたは全文が空の項目は表示に使わない（編集画面に理由を表示する）
- 1 画面の項目数（緊急・戻る・遷移項目を含む）が目安の 8 を超える場合は警告し、項目を減らすか画面を分けるよう促す（保存は妨げない。1 グループの安全上限は 20 項目）
- 分類ごとの初期値に戻すボタンは持たない（Issue #154）。フレーズを戻す操作は「フレーズ」タブ末尾の「初期値に戻す」（§6）にまとめ、全分類のフレーズが一度に戻る
- 編集内容は設定と同じく localStorage（ルートキー `libra` の `phrases`）に保存する
- 設定全体（フレーズを含む）を JSON で書き出し・取り込みできる。端末の入れ替え用。書き出しには識別子（`app: "libra"`・`version`）とフレーズの移行済みの印（`phrasesVersion`。§4.1.3）を入れ、無い・合わない JSON、壊れた JSON は取り込まず今の設定を保つ。取り込みは確認（2 回押し）を挟み、今の設定を土台に、書き出しに含まれる検証済みの項目だけを上書きする（欠けた・範囲外の項目は今の値のまま。本人に合わせたスキャン設定が黙って既定値に戻らない）

## 7. 音

緊急警告音は鳴らさない（Issue #43）。緊急は画面上部の視覚表示と振動（§7.1）で伝える。以下は音声モード・聴覚スキャンの扱い。

| 種類           | 音声モード OFF | 効果音だけ | 短く読む   | 全部読む   |
| -------------- | -------------- | ---------- | ---------- | ---------- |
| 伝達の読み上げ | なし           | 効果音     | 短文       | 全文       |
| 聴覚スキャン   | 設定に従う     | 設定に従う | 設定に従う | 設定に従う |

### 7.1 本人への触覚フィードバック

入力の結果を、本人が他人の反応なしに知るための出力。目や耳を使いにくい人にも届くよう、振動で返す。パターンは `lib/feedback.ts` に集約し、互いに区別できる（テストで重複がないことを確認）。

| イベント                                  | 振動（標準・ms。振動・休止・振動…）                  |
| ----------------------------------------- | ---------------------------------------------------- |
| 入力受理（項目を実行した）                | 20                                                   |
| 伝達（はい・いいえ以外）                  | 40                                                   |
| はい                                      | 120（長め1回）                                       |
| いいえ                                    | 120・100・120（長め2回）                             |
| 緊急色の伝達（緊急の詳細など）            | 60・40・60                                           |
| 緊急を呼び出した                          | 300・120・300・120・300                              |
| 緊急の呼び出し中                          | 50・60・50・60・50（小さく3回）を 3 秒周期で繰り返す |
| 緊急の解除（介助者の解除・本人による解除。§4.3） | 500                                                  |
| 伝達済み（介助者の応答を受信。#9 で使う） | 100・80・100・80・100・80・100                       |

- 受理の振動のあとに伝達・緊急のパターンが続くため、実際に感じるのは後のパターン（新しい振動が直前の振動を置き換える）
- 緊急の呼び出し中の周期の振動は、3 秒周期で繰り返す。**本人が入力した直後（周期の長さの間）は、周期の振動を出さない**（はい・いいえなどの振動を打ち消さない・取り違えさせないため）
- 再読み込み・再起動で緊急が復元された場合も、周期の振動を続ける（復元の直後に、緊急発生時の長い振動は出さない）。ただしブラウザは、画面に一度も触れていないページの振動を無視するため、実際に振動し始めるのは本人か介助者が一度画面に触れてから
- 振動のパターンは、標準で最低 20ms（多くの振動モーターが感じられる長さ）の振動を保つ。受理・伝達・はいは長さだけが違う単発の振動で、実機（Android）で区別できるかは確認待ち
- 介助者設定: 振動の ON/OFF（既定 ON）、強さ（弱・標準・強。振動する長さだけを 0.6 / 1 / 1.6 倍し、合間は変えない）
- **Vibration API が無い端末**（iOS Safari など）は、同じパターンを短い効果音で代替する。音声モード OFF のときに鳴らすかは設定で選べる（既定は鳴らさない）
- **振動モーターのない端末**（タブレット・デスクトップのブラウザなど。API はあっても振動しない）は、API の有無から見分けられないため、介助者設定「振動に加えて、いつも短い効果音でも知らせる」（既定 OFF）で効果音を足す
- AudioContext が使えないときは効果音を出さない。新しい効果音は直前の効果音を止めて置き換える。緊急・緊急の呼び出し中は、効果音は重ねない（振動だけ出す）
- 音声モード「効果音だけ」は、触覚フィードバックが ON のときはこの層の振動で代える（区別できるパターンを打ち消さない）。OFF のときだけ従来の短い振動を出す
- Phase 2（本人が握る外部触覚デバイス・点字セル）は調査段階であり、本書の範囲外

## 8. 限界（明記事項）

- Libra はナースコールの置き換えではない
- 本人がスイッチを押せないほど急変した場合は機能しない
- バックエンドが落ちていても、すべての伝達機能はオフラインで動かなければならない
- アプリが外部へ通信するのは、介助者用メニュー「このアプリ」タブの利用回数の取得（起動ごとに 1 回。§6）だけ。失敗・遅延・オフラインでも、伝達機能・スキャン・緊急には影響しない（結果を待たず、失敗は「取得できません」と表示するだけ）。好きな画像（§5）・設定・緊急状態・伝達の履歴は、端末の外へ送らない
- Bluetooth シャッターが送るキーは機種により異なり、ブラウザに届かないもの（一部の音量キー等）がある。対応機種は実機確認で確定する
