# Libra — 対応プラットフォーム

Libra はブラウザで動く Web アプリとして設計する。

## 第一対象

- タブレット
- ベッド横の机に立てかけた常設端末
- スマホ

## 入力

- タッチ
- キーボード
- 任意のキー（Space / Enter / 音量キー等）として届く外部ボタン
- Bluetooth シャッターボタン

## PWA

ホーム画面に追加すると `display: fullscreen`（非対応環境では `standalone`）で起動し、ブラウザの UI が隠れた状態で使える。アプリ内の「全画面にする」ボタンはない（Issue #119）ので、全画面で使うにはホーム画面に追加（インストール）して開く。介助者用メニュー「使用準備」タブには、ブラウザが受け付ける場合はインストールのボタン、受け付けない場合（iOS の Safari など）は手順が出る（Issue #158。Android と iOS の実機は未確認）。

## 常設運用時の端末設定（推奨）

ベッド横に常設し、タイル直接タップと外部スイッチ（キー）で操作する想定（`docs/requirements.md` §3, §8）。Libra 自体の機能で対策していることと、端末側で設定してほしいことを分けて書く。

- **端末の自動ロック（画面消灯）は OFF にする**: Libra は起動時に Screen Wake Lock API で画面消灯を防ぎ、タブが再表示されたときも再取得する。ただし OS 側の設定次第では効かない場合があるため、介助者用メニュー「使用準備」タブの「画面スリープ防止」表示が有効になっているか確認する。非対応/失敗時はそこに端末側の設定を促す文言が出る
- **常時充電しながら使う**: 画面を常時点灯させ続けるとバッテリー消耗が早い
- **ホーム画面に追加（インストール）して起動する**: 全画面になり、ブラウザの戻る操作やタブ切り替えなどの誤操作経路を減らせる
- **通信が必要なのは、介助者用メニュー「このアプリ」タブの利用回数・リンクだけ**: 利用回数は起動ごとに 1 回取得する。取得できなくても伝達機能は止まらない
- **オフラインでも動く**: Service Worker がアプリ本体（HTML/JS/CSS/フォント/アイコン）を事前キャッシュしているため、ネットワーク断・バックエンド停止でも緊急・はい/いいえ等の伝達は動作を続ける
