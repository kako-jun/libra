# Libra 格子状 UI 規約

Libra は Esuna と同じく「大きな矩形を押す」設計を採用する。ただし Esuna の 9 マス固定レイアウトは採用しない。

## 原則

- タイルは大きく、遠目で読める
- 隙間なしの格子: タイル間の gap・角丸・影は使わない。セルは右+下の細い区切り線
  (トークン `--grid-line`/`--grid-line-width`。高コントラストで太くなる)だけで
  区切り、メッセージ欄・文字盤入力欄も含めて画面全体が一枚の盤に見えるようにする
- **全タイルを同じ大きさにする(Issue #47)**: 項目数でタイルの大きさを変えない。
  通常のスキャン画面(1画面8項目以内)は、**画面の向きだけで決まる固定格子**を全画面で
  共有する(`computeGridLayout`)。縦長(高さ >= 幅。正方形を含む)は **2列×4行**、横長(幅 > 高さ)は
  **4列×2行**。どちらも8セルで、8項目(ホームの「直前を取り消す」込み)がちょうど埋まる。
  判定はビューポートの縦横で行い、項目数・緊急中・伝達メッセージの有無・文字サイズでは
  変わらない(格子領域の実測を使うと、緊急帯・伝達メッセージ・案内帯の増減で画面ごとに
  格子が切り替わってしまうため)。項目が8未満のときは、末尾のセルを**空きセル**として残す。
  最後のタイルを引き延ばしたり、列数・行数を項目数に合わせて変えたりしない。
  緊急・戻る・通常の選択肢も同じ大きさで、画面ごとの例外は作らない
- **空きセル**(`.tile-empty`)はタイルではない。面の色も区切り線も持たず盤の背景がそのまま
  見える「何もない」セルで、スキャン順・タップ・キー操作・読み上げ(`aria-hidden`)の対象外。
  押しても何も起きない(背景タップと同じ)
- 文字サイズ設定が大きい場合も、セルを増減させるのではなく、タイル内の文字をそのセルに
  収まる範囲で最大まで大きくする(CSSの `--tile-label-font` 側、`--label-ratio` 変数
  (標準0.85/大0.93/特大1.0)で処理する。メッセージ欄の見出しの大きさは文字サイズ設定の
  対象外なので、格子の面積が文字サイズ設定で変わることはない)。8項目以内の画面は
  文字サイズ設定に関係なく常に全面充填し、スクロールしない。文字盤の行段階(15項目)だけが
  設計上スクロールする
- **スキャン枠の余白(Issue #34)**: スキャン枠(黄色リング一本)はセルの縁から
  `--scan-ring-inset`(= 4px + リングの太さ + 2px。標準12px、高コントラスト15px。ただし高さ500px以下、
  または幅480px以下かつ高さ700px以下の画面では、高コントラストの枠を7pxにして帯は13px)の帯を占める。
  タイルの余白・山形アイコン・下部の予告は、スキャン中でなくても常にこの帯の内側に置く
  (枠が来ても文字を隠さず、選択で位置・大きさが変わらない)。ラベルの文字サイズの
  基準(`--tile-label-font` の cqi/cqb)は、この帯が太い高コントラストでも標準と同じ大きさに
  保つよう `--ring-extra`(標準との差)で補正する。セルの高さが2行ぶん足りないときだけ、
  ラベルの下限(1.05rem)をセルの高さに合わせて下げ(13px 未満にはしない)、2行ラベルが帯に入らないようにする。
  足りない高さは文字を縮めずセル側で確保する(短い画面は緊急の帯を1行にし、高コントラストの枠は
  短い画面、または幅480px以下かつ高さ700px以下の画面で7pxにする)。測定: DESIGN.md §11
- スクロールする画面(文字盤)では、巡回中に緊急タイルが画面外へ
  出ないよう、緊急タイルを `position: sticky` で可視範囲に留め、各タイルに
  `scroll-margin-top`(sticky分の高さ)と `scroll-margin-bottom`(8px)を
  付けて `scrollIntoView` が上下とも隠れた位置に止まらないようにする
  (画面の物理的な高さが足りず両立できない極端な組み合わせでは、緊急タイルの
  可視性を優先する)
- 赤は上部メッセージ欄(緊急状態帯・緊急色調のメッセージ)だけに使い、タイルは
  赤くしない(Issue #36)。緊急入口タイルも装飾せず通常面のまま、ラベル「緊急」・
  固定位置(ホームは先頭、下位画面は2番目)・上部の緊急状態帯の文言で区別する
- 選択中の自動スキャン対象は、暗い面への反転 + セル内側に収まる(隣のセルへ
  はみ出さない)黄色枠一本で示す。黄色単体は白背景に1.53:1で3:1に届かないため、
  アウトラインを重ねる代わりに面を暗くして黄色枠が3:1以上になるようにする
  (白縁・二重枠なし、Issue #33。実測は DESIGN §2)。隙間なし格子では
  拡大(scale)すると隣のセルと重なるため使わない
- ホームは「緊急」を先頭に置き、通常下位画面は「戻る」を先頭、「緊急」を2番目に置く。緊急詳細は「戻る」が先頭
- メッセージ表示エリアは常に画面上部に固定する。アプリ名・音声モード・
  スキャン位置などの状態表示は置かない(本人はカーソルの強調で位置が分かる)
- 下位画面へ進むタイルは、ラベル末尾に矢印文字を置かず、右端の山形アイコン
  (インラインSVG)+ 下部の中身の予告(遷移先メニューから自動生成)で示す。
  読み上げはラベルのみで、アイコン・予告は読まない

## 操作

本人の操作はシングルスイッチ自動スキャン（キー/外部スイッチ）だけで全伝達が成り立つ。タイルの直接タップは追加経路（正本: `requirements.md`）。

| 入力                            | 動作                                                                   |
| ------------------------------- | ---------------------------------------------------------------------- |
| 任意キー / Bluetooth シャッター | 現在のスキャン対象を実行                                               |
| タイルの直接タップ / クリック   | 押したタイルを実行（スキャン位置とは無関係。背景のタップは何もしない） |
| 介助者ボタンのクリック / タップ | 介助者メニュー（設定・緊急解除）                                       |

以下は開発・介助者向けの補助で、本人の経路には使わない。

| 入力    | 動作                                                                                                                                                                    |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `1`-`9` | `?dev` 付き URL のときのみ有効。画面上の先頭9タイルを直接実行する（番号表示も `?dev` のときのみ。通常時は数字キーも任意キーと同じ扱いで、現在のスキャン対象を実行する） |

## Esuna との差分

Esuna は視覚障害者向けの一貫操作として 9 マスの意味を固定する。

Libra はベッドサイドで本人と周囲が同時に見るため、タイル数は画面や用途で変えてよいが、格子の形(配置)は画面の向きで固定する(2列×4行 / 4列×2行)。固定するのは「格子状で押しやすい」「現在のメッセージが大きく見える」という体験である。
