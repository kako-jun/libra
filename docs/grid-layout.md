# Libra 格子状 UI 規約

Libra は Esuna と同じく「大きな矩形を押す」設計を採用する。ただし Esuna の 9 マス固定レイアウトは採用しない。

## 原則

- タイルは大きく、遠目で読める
- 隙間なしの格子: タイル間の gap・角丸・影は使わない。セルは右+下の細い区切り線
  (トークン `--grid-line`/`--grid-line-width`。高コントラストで太くなる)だけで
  区切り、メッセージ欄・文字盤入力欄も含めて画面全体が一枚の盤に見えるようにする
- 項目数と格子領域の実測サイズ(縦横比)から列数・行数を自動算出し、
  孤立タイルや下部の空白を出さずに格子領域全体をタイルで敷き詰める
  (`computeGridLayout`、目安8項目以内の画面が対象。8項目以内の画面は
  文字サイズ設定に関係なく常に全面充填し、スクロールしない。文字盤等
  それを超える画面だけがスクロールする)。最後の行に空きが出る場合は
  最後のタイルを横に伸ばして埋める(spanは最大2まで)。最小セル寸法
  (既定160×84px、文字サイズ設定に関係なく固定)を下回る列数の候補、および
  「帯」(列数か行数の一方が1で、もう一方が5以上)になる候補は、最小セル寸法を
  満たしていても最初から除外する。候補の評価は「ラベル文字が最大何pxまで
  大きくなれるか」(`min(labelWidthFactor*セル幅, labelHeightFactor*セル高さ)`。
  既定値は0.15/0.20(`DEFAULT_LABEL_WIDTH_FACTOR`/`DEFAULT_LABEL_HEIGHT_FACTOR`)
  だが、実際には CSS 側の `--label-cqi`/`--label-cqb`(ブレークポイントごとに
  基本15/20、720px以下20/22、480px以下22/24)を `App.tsx` が
  `getComputedStyle` で読んで毎回渡す。CSSとJSで係数をそれぞれハードコードして
  一致を祈るのではなく、CSS側の実効値をJS側にそのまま流し込むことで、
  「ラベルが実際に描画されるサイズ」と「JSが候補選びに使うスコア」を
  常に一致させている)を主キーに最大化する候補を選ぶ。空きセル数(0か1のみ
  許可、spanは最大2まで)はスコアへの小さな減点(0.5px×空きセル数)として
  組み込まれており、僅差の候補間のタイブレークとしてのみ働く(空きセル数を
  最優先にすると、項目数によっては「空きセル0だが1列の帯」が「空きセル1だが
  ずっと大きい2列」より選ばれてしまうため)。文字サイズ設定が大きい場合、
  セルそのものを増減させるのではなく、タイル内の文字をそのセルに収まる範囲で
  最大まで大きくする(CSSの `--tile-label-font` 側、`--label-ratio` 変数
  (標準0.85/大0.93/特大1.0)で処理する。メッセージ欄の見出しの大きさは
  文字サイズ設定の対象外なので、格子の面積が文字サイズ設定で変わることはない)。
  最小セル高さを満たす候補が1つも無い場合(568×320のような横向きの極端に
  低い画面など)、既定の最小セル高さ(84px)より緩めた `RELAXED_MIN_CELL_HEIGHT`
  (50px)で一度だけ再探索し、それでも無ければ現行のスクロール表示に倒す
  (スコアの計算式自体は変えない、あくまで最後の手段としての下限)。
  スクロールする画面(文字盤)では、巡回中に緊急タイル(常に先頭)が画面外へ
  出ないよう、緊急タイルを `position: sticky` で可視範囲に留め、各タイルに
  `scroll-margin-top`(sticky分の高さ)と `scroll-margin-bottom`(8px)を
  付けて `scrollIntoView` が上下とも隠れた位置に止まらないようにする
  (画面の物理的な高さが足りず両立できない極端な組み合わせでは、緊急タイルの
  可視性を優先する)
- 緊急タイルは赤系のベタ塗り、通常タイルは面の色(塗り分け)で区別する。
  さらに色以外でも判別できるよう、緊急タイルには常時、内側に白系の輪郭
  (色覚特性への配慮)を付ける
- 選択中の自動スキャン対象は、セル内側に収まる(隣のセルへはみ出さない)
  黄色枠 + 面の色変化で示す。黄色単体では白背景等に対するWCAG非テキスト
  コントラスト(3:1)を満たさないため、濃色(または明色、テーマ・タイルの色調に
  応じて自動選択)のアウトラインを重ねた二重枠にしている。隙間なし格子では
  拡大(scale)すると隣のセルと重なるため使わない
- どの画面でもスキャン1周の先頭は「緊急」
- メッセージ表示エリアは常に画面上部に固定する。アプリ名・音声モード・
  スキャン位置などの状態表示は置かない(本人はカーソルの強調で位置が分かる)
- 下位画面へ進むタイルは、ラベル末尾に矢印文字を置かず、右端の山形アイコン
  (インラインSVG)+ 下部の中身の予告(遷移先メニューから自動生成)で示す。
  読み上げはラベルのみで、アイコン・予告は読まない

## 操作

本人の操作はシングルスイッチ自動スキャンのみ（正本: `requirements.md`）。

| 入力                                     | 動作                                         |
| ---------------------------------------- | -------------------------------------------- |
| タップ / 任意キー / Bluetooth シャッター | 現在のスキャン対象を実行（本人の唯一の入力） |
| 介助者ボタン長押し（2 秒）               | 介助者メニュー（設定・緊急解除）             |

以下は開発・介助者向けの補助で、本人の経路には使わない。

| 入力    | 動作                                                                                                                                                                    |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `1`-`9` | `?dev` 付き URL のときのみ有効。画面上の先頭9タイルを直接実行する（番号表示も `?dev` のときのみ。通常時は数字キーも任意キーと同じ扱いで、現在のスキャン対象を実行する） |

## Esuna との差分

Esuna は視覚障害者向けの一貫操作として 9 マスの意味を固定する。

Libra はベッドサイドで本人と周囲が同時に見るため、タイル数・配置は画面や用途で変えてよい。固定するのは「格子状で押しやすい」「現在のメッセージが大きく見える」という体験である。
