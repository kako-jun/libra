# Libra — 概要

`libra` は病棟ベッドサイド向けの超軽量コミュニケーション補助アプリ。

`esuna` が本人ひとりでも成立する娯楽・気分転換のためのアプリであるのに対し、`libra` は患者本人と周囲の人のあいだで意思を伝えるための道具に絞る。

## 基本方針

このアプリの本体は、質問に対して「はい」「いいえ」を確実に伝えることである。用途は優先順に、①質問に対する受動の答え（はい／いいえ、続けて／やめて／変えて）、②緊急を能動的に知らせる、③余裕があれば会話を能動的に伝える（不快・要望・気分・文字盤。Issue #93 で、①に属する「続けて・やめて・変えて」を「快」として要望・気分と分けた）。③は付け足しであり、①②を最速・最大・最も確実にすることを基本とする。はい／いいえは介助者が口頭で聞いた質問への答えにも使われるので、アプリが肯定・否定の意味を解釈しない。

## 立ち位置

- ナースコールの置き換えではない
- 病院全体システムの置き換えでもない
- その手前 / 横に置く
- 家族や介助者が横にいる場面で使う
- スマホやタブレットだけで導入できる

## 基本導線

要件の正本は `requirements.md`。

- 本人はシングルスイッチ自動スキャン（キー/外部スイッチ）だけで全伝達ができる。タイルの直接タップは追加経路
- ホームの巡回順: 緊急 →（伝達直後の2周だけ 取り消し）→ はい → いいえ → 快 → 不快 → 要望 → 文字盤 →（設定ON時のみ モールス）
- 設定は介助者用ボタンの通常のクリック/タップ（フォーカス時は Enter / Space）で開き、本人のスキャン巡回には含めない

緊急導線と深い入力導線を混ぜない。ホームは緊急を先頭に置き、通常下位画面は戻るを先頭、緊急を2番目に置く。緊急詳細は戻るを先頭にし、緊急タイルを重複させない。

## UI 方針

Esuna のような押しやすい格子状UIを踏襲する。ただし Libra は 9 分割固定ではない。

格子の形は画面の向きだけで決まる（縦長 2列×4行 / 横長 4列×2行）。項目が少ない画面でもタイルは引き延ばさず、余りは空きセルとして残す（`grid-layout.md`）。重要なのは、遠目でも読める大きさ、押し間違いにくい余白、状態が一目で分かる大きな表示である。
