# Libra トラブルシューティング

## 音声が出ない

- 端末の音量を確認する
- Libra の音声モードが OFF になっていないか確認する
- ブラウザが Web Speech API をサポートしているか確認する

## キー / Bluetooth ボタンで決定できない

- スキャンは起動時から常に動いている（開始操作はない）。ブラウザのタブが前面にあり、ページにフォーカスがあるか確認する
- 介助者メニューを開いたままでないか確認する（開いている間のキー入力は、何も実行せずメニューを閉じるだけ。例外は、タブ上の ←/→/Home/End と、入力欄・スライダー・チェックボックス操作中の編集キー）
- 連打無視・押下時間の下限・離して決定の設定が効いていないか確認する（該当するときは画面下の案内に理由つきで出ている）
- Bluetooth ボタンの場合、OS 上でキーボード入力として認識されているか確認する

## 文字が小さい

介助者メニューの「表示」タブで文字サイズを「大」「特大」にする。

## 画面が見づらい

介助者メニューの「表示」タブで「高コントラスト」を ON にする。

## 画面がすぐ暗くなる・ロックされる

- 介助者メニューの「画面スリープ防止」表示を確認する。「有効」なら Libra 側は正常に画面消灯を防いでいる
- 「無効」の場合、端末（OS）側の自動ロック設定を OFF にする。Screen Wake Lock API 非対応のブラウザ・環境ではこの表示になり、Libra 側では画面消灯を防げない
- タブを切り替えて戻ってきた直後は再取得を試みるが、OS 側で自動ロックがかかった後だと本人操作が届かないことがあるため、端末側の自動ロック OFF を優先する

## 画面が拡大される・スクロールしてしまう・文字が選択される

常設運用中の誤操作（連続タップ・長押し・ピンチ）による拡大やスクロール、テキスト選択、長押しメニューは通常発生しない。viewport に `user-scalable=no` を指定しているのもこの誤拡大防止のためで、意図した挙動。もし起きる場合:

- ホーム画面に追加して全画面（`fullscreen`/`standalone`）で開いているか確認する。ブラウザのタブ内でそのまま開いていると、ブラウザ自体のピンチ操作が優先されることがある
- 介助者メニューの「全画面にする」を試す
- 画面全体が動く・ヘッダが見切れる・フッタが下端から浮く場合: 画面全体（ドキュメント）は構造上スクロールしない作り（Issue #84）。ブラウザのアドレスバーの出入りがある環境では、ホーム画面に追加して全画面で開くと再現しないか確認し、再現するなら端末・ブラウザ・向きを添えて報告する（実機での確認は未了）

## オフラインで動かない

- 一度オンラインの状態で Libra を開き、Service Worker が有効化されるまで数秒待ってからオフラインにする（初回アクセス時にアプリ本体をキャッシュするため）
- ブラウザの設定でサイトデータ・キャッシュを消去していないか確認する
- バックエンドとの通信（設定同期等）が失敗しても、緊急・はい/いいえ等の伝達自体は止まらない（`docs/requirements.md` §8）
- 介助者メニューの「オフライン準備」が「未完了」のままの場合、通信が安定しているときにページを再読み込みする。初回の取得に失敗した場合も含めて、未完了のあいだは自動で再登録・再取得を試み続ける。再試行の間隔は5分から始まり、失敗するたびに2倍に延びていく（10分・20分…上限60分）ので、通信状態が悪いままだと間隔が徐々に空いていく。介助者メニューを開いたときは、その場でも再取得を試みる。回線が完全に切れている（オフライン）ときは無駄な再試行はせず、繋がってから改めて試みる
