# Libra — 機能一覧

詳細・優先順位の正本は `requirements.md`。

## 見出し(メッセージ欄)

- 上部のメッセージは 1 行に収まる最大サイズで表示する（収まらないほど長い文だけ従来どおり折り返す）。文字サイズ設定の対象外
- 画面上部は 緊急の表示 → 「直前に伝えたこと」 → 現在地・画面の案内 の順（Issue #114）
- **伝達の履歴（Issue #120）**: 枠の左右の矢印（介助者がタップ / クリックで使う。スキャン対象ではない）で、過去の伝達を振り返れる（「過去に伝えたこと（N件前）」）。端末のメモリ内だけに最大 50 件。取り消した伝達は履歴からも消える。最新が空で履歴が残るときは「いまは、伝えたことがありません。」を出す
- 現在地の先頭「ホーム」には家のアイコンを付ける（Issue #113）

## 押すと伝達欄が赤くなるパネル

- 「苦しい」、痛みの強さの「とても」、「胸」を選んだ後の「場所だけ・少し・かなり・とても」など、押すと伝達欄が赤くなるパネルは、押す前から赤みのある色にする（ライトは淡いピンク、夜間は赤茶。Issue #136）。画面遷移だけのパネル・緊急パネル・緊急の詳細は色を変えない

## 緊急

- 選択した瞬間に「緊急です。来てください。」を赤で大きく表示する（緊急警告音は鳴らさない。解除まで静かな視覚表示が残る）
- 確認手順なし。介助者が解除するか、本人が 緊急 → 緊急を解除 → 解除する を選ぶまで表示が残る（再読み込み・再起動後も復元）
- 任意で詳細: 苦しい / 痛い / 息ができない / 吐きそう / 胸が痛い
- **本人による解除（Issue #108）**: 緊急詳細の末尾の「緊急を解除」→ 確認画面（戻る / 解除する）で「解除する」を選ぶと解除する。確認画面の先頭は「戻る」で、無入力 3 周ならホームへ戻り緊急は残る。解除すると振動（500ms）と、伝達欄の解除の文（選んだ詳細を含む。例「緊急（息ができない）を解除しました。」）の表示・読み上げで知らせる。緊急の呼び出しと詳細は伝達の履歴にも残り、解除の後も矢印で振り返れる。取り消しは出ない
- **緊急中は、解除の操作以外の本人入力で上書きされない**。緊急中に「はい」等の伝達を選んでも、見出しの緊急表示・赤背景は変えず、選んだ内容は「直前に伝えたこと」領域へ別に表示するだけ。取り消しも緊急中は出さない

## もう一度

ホームの緊急の次に置く常設の項目（Issue #123）。聞き逃されたとき、直前の伝達をもう一度伝える（同じ振動パターン・読み上げ・表示の点滅。見出しは「直前に伝えたこと（もう一度）」）。伝達が無い間は薄く表示し、押しても何も伝えない（位置は空けない）。緊急中で伝達が無いときは、緊急の呼び出しをもう一度伝える。履歴・取り消しの猶予は変えない。

## はい / いいえ

ホームで緊急・もう一度の次に置く。質問への応答が最も頻度が高い。

- **取り消し**: 伝達の直後の2周だけ出る。選ぶと「直前に伝えたこと」が消えて、何も伝えていない状態に戻る（1つ前の返事は復元しない）。緊急中は出さない

## 不快

痛い（場所）/ 苦しい / 痰 / 体の向き / トイレ / その他 →（暑い / 寒い / 喉が渇いた / かゆい / 眠れない）

**痛みの強さ**: 痛い場所を選ぶと、続けて「場所だけ / 少し / かなり / とても」を選べる。不快 → 痛い → 胸 → とても で「胸がとても痛いです。」（緊急色）が伝わる。「場所だけ」を先頭に置き、強さを選べなくても最短で伝えられる。

1画面の項目数は緊急・戻るを含めて8以内（requirements.md §4.1）。頻度の低い項目は「その他」に退避する。

## 快

続けて / やめて / 変えて / 気分 →

- 二値の入口「続けて・やめて・変えて」を最上位に置く（編集できない固定項目）
- 気分 →: 不安 / さみしい / 落ち着かない

## 要望

ホームから直接開く（Issue #93。以前は「快・要望」の中の「要望 →」だった）。

- 大丈夫 / ありがとう / 眠りたい / 静かにしてほしい / 家族に会いたい / 話したい（テレビ・音楽などはフレーズ編集で追加できる）

## 文字盤

最後の手段。清音 46 字 + 「ー」。行 → 文字の2段階スキャン。行段階の並びは 戻る / 緊急 / 1字消す / あ行〜わ行 / 確定（14 項目。Issue #121）で、15 セルの専用格子に収めてスクロールしない。入力途中の文字列を常に大きく表示し、周囲の先読みを「はい / いいえ」で受ける（答えはホームの「はい」「いいえ」。文字盤の中には置かない、Issue #95）。

## 格子とタイルの表示

- 格子は画面ごとに決まる 3 種類（標準 8 セル / ホーム 10 セル（幅 600px 以上の縦長は 3×3 の 9 セル）/ 文字盤の行段階 15 セル。正本: `grid-layout.md`）。ホームと下位画面ではタイルの大きさが違う。セル数を超えた画面（フレーズを増やした画面）だけスクロールする
- タイルのアイコン（Issue #115）: ホームの全項目と「戻る」に、文字と同じ色の線画を添える（読み上げ対象外。高いセルではラベルの上、低いセルでは同じ行。文字サイズ「大」「特大」で低いセルのときはアイコンを隠して文字を大きくする）
- 好きな画像（Issue #122）: 「介助者用」ボタンの左に表示。端末の中だけに保存し、設定の書き出しには含まれない

## シングルスイッチ自動スキャン

- 起動時から常時動作。本人の入力は2経路だけ
- 任意キー / Bluetooth シャッターは同じオンとして現在のスキャン対象を実行する
- タイルの直接タップ/クリックは押したタイルを実行する（スキャン位置と無関係・二重実行しない）。画面の背景のタップは何も実行しない。タイルは role=button・aria-label を持つ
- スキャン間隔・先頭待機（既定は間隔の 4/3 倍＝1.5 秒間隔で 2.0 秒。Issue #92）・連打無視・押下時間の下限・決定タイミング・聴覚スキャンを介助者が設定（localStorage 保存）

## モールス入力（上級者向け・既定OFF）

介助者が設定で ON にしたときだけ、ホームの最後に「モールス」が出る。短押し＝短点・長押し＝長点で和文モールスの文字を入力する。SOS（・・・－－－・・・）を休まず続けて打つと即緊急。画面に操作と自動挙動の凡例を常時出す（requirements.md §4.7）。

## 触覚フィードバック

入力の受理・はい/いいえ・緊急・解除を、区別できる振動パターンで本人に返す。振動できない端末では、音声モードが OFF 以外、または設定「振動できない端末では、音声OFFでも短い効果音で知らせる」が ON（既定 OFF）のときだけ、短い効果音で代替する。緊急（呼び出し・呼び出し中）は効果音を出さず振動だけ（#43）。詳細は requirements.md §7.1。

## 常時案内

画面を見れば分かることは、どこにも書かない（Issue #79）。本人画面の下端には緊急中の振動の案内だけを出す（緊急でないときは何も出さない）。介助者用メニュー上部の固定説明は削除した（Issue #138。動きは変えない）。設定に応じた見ても分からない動作（連打無視・押し方・読み上げの割り込み）は、「スキャン」タブの原因の設定のすぐ下に出す（Issue #111。旧「状態」タブの「いまの動作」は廃止）。隠す操作はない（requirements.md §4.1.2）。

## 音声モード

- OFF
- 効果音だけ
- 短く読む
- 全部読む

相部屋や夜間に配慮し、デフォルトは OFF。緊急でも警告音は鳴らさない（視覚表示と振動で伝える）。

## 介助者用メニュー

- タブ: 使用準備 / スキャン / 音と振動 / 表示 / フレーズ / モールス / データ / このアプリ。タブが続くときは続きがある側に矢印を出す。設定の書き出し・取り込みは「データ」
- 「緊急を解除」は緊急中だけ、左右の中央に出る（Issue #137・#152）
- 介助者用メニューの文字は 16px の通常の太さ。見出しだけ少し強くする（Issue #163。本人画面は変えない）
- スライダーは左右の矢印で 1 段階ずつ調整できる（Issue #141）
- 「使用準備」タブから、アプリをインストールできる。ボタンから出せない環境は手順を示し、インストール済みの版ではその旨を示す（Issue #158。実機は未確認）
- 「初期値に戻す」はタブごと（スキャン・モールス・音と振動・表示・フレーズ。Issue #117）。2 回押しで実行し、そのタブの設定だけを戻す。旧「設定全体を既定に戻す」は廃止
- 「このアプリ」: 使い方・「くわしい使い方」・掲示板・作者サイトのリンク、利用回数（Nostalgic カウンター。本番のホストで開いたときだけ起動ごとに 1 回数え、失敗しても伝達に影響しない）、バージョン（Issue #118）
- 「全画面にする」ボタンは削除した（Issue #119）。常設するときはホーム画面に追加して開く

## 常設運用（画面スリープ防止・オフライン動作・全画面）

ベッド横に常設し、タイル直接タップと外部スイッチ（キー）で操作する運用を前提にした堅牢化（requirements.md §8, Issue #5）。

- **画面スリープ防止**: Screen Wake Lock API を起動時に取得し、タブが再表示されたときに再取得する。可視のままエラー/自動解放になった場合も、本人のスイッチ入力(タップ/キー)のたびと 30 秒間隔のタイマーで再取得を試みる。状態(有効/無効)を介助者用メニュー「使用準備」タブに表示し、非対応/失敗時は端末の自動ロックを切るよう促す
- **フォント**: 入力欄・ボタンを含む全ての文字を BIZ UDGothic の1種類で表示する(予備フォントの指定は無い)。書体が持つ全 11741 字を同梱し、オフラインでも同じ書体になる。書体に無い字(✔ ✕ ☑ 𠮷 や絵文字など。JIS X 0208 と Windows の CP932 の2バイト文字はすべて書体にある)は端末の別の書体で表示される。ディスレクシアへの対応はうたわない。フォントの読み込みに失敗した場合は、予備フォントを指定していないのでブラウザの既定の書体になる(端末の既定が明朝なら明朝になりうる。末尾の `sans-serif` も指定していない)。ライセンス(OFL 1.1)の全文は配信物の `licenses/BIZUDGothic-OFL.txt` にある(アプリ内からのリンクは無い)
- **オフライン動作**: Service Worker がアプリ本体(HTML/JS/CSS/フォント/アイコン)をビルド時に丸ごと precache し、ネットワーク断・バックエンド停止でも緊急・はい/いいえ等の全伝達がオフラインで動く。ナビゲーションは3秒タイムアウト付き network-first で、失敗時はキャッシュへ確実にフォールバックする(precache自体がまだ無い初回アクセス等は、諦めずネットワークの応答を待ち続ける)。install が途中で失敗した場合は既存の版がそのまま動き続ける。初回のオフライン準備はフォントを含めて約 9.2MB を受け取るので、回線は 0.5 Mbps 以上が目安(実測の条件と値は architecture.md)
- **オフライン準備の表示**: 介助者用メニュー「使用準備」タブの「オフライン準備: 完了/未完了」は、Service Worker がこのページを制御しているか(controller)だけでなく、現在ロードしているページが実際に参照している URL(`/` と JS/CSS。フォントは含めない — install は全件成功/全件失敗の一体なので、本体が揃っているならフォントも揃っている)が Cache に揃っているかまで確認して判定する。通常のクリック/タップで介助者用メニューを開くたびに再計算し、未完了のあいだは Service Worker の更新チェック(既存の registration が無ければ再登録)を試みる。再試行の間隔は5分から始まり、失敗するたびに倍(上限60分)に伸ばす(指数バックオフ。完了すれば5分にリセット)。オフライン中(`navigator.onLine===false`)は無駄な再試行をしない
- **全画面**: PWA manifest は `display: fullscreen`(非対応環境では `standalone`)。ホーム画面に追加(インストール)して開くと全画面になる。アプリ内の「全画面にする」ボタンは Issue #119 で削除した
- **誤作動防止**: ダブルタップ拡大・ピンチ拡大・pull-to-refresh・スクロール・テキスト選択・長押しコンテキストメニューを本人画面全体で抑止する。介助者用メニュー内の操作は妨げない。orientation は縦横両対応(`any`)。格子はセル数に収まる画面ではスクロールしない(文字盤の行段階も 15 セルの専用格子に収まる。Issue #121)。介助者がフレーズを増やしてセル数を超えた画面だけはスクロールし、スキャン対象が変わるたびに画面内へ自動でスクロールする
