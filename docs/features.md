# Libra — 機能一覧

詳細・優先順位の正本は `requirements.md`。

## 見出し(メッセージ欄)

- 上部のメッセージは 1 行に収まる最大サイズで表示する（収まらないほど長い文だけ従来どおり折り返す）。文字サイズ設定の対象外

## 緊急

- 選択した瞬間に「緊急です。来てください。」を赤で大きく表示する（緊急警告音は鳴らさない。解除まで静かな視覚表示が残る）
- 確認手順なし。介助者が解除するまで表示が残る（再読み込み・再起動後も復元）
- 任意で詳細: 苦しい / 痛い / 息ができない / 吐きそう / 胸が痛い
- **緊急中は本人入力で上書きされない**。緊急中に「はい」等の伝達を選んでも、見出しの緊急表示・赤背景は変えず、選んだ内容は「直前に伝えたこと」領域へ別に表示するだけ。取り消しも緊急中は出さない

## はい / いいえ

ホームで緊急の次に置く。質問への応答が最も頻度が高い。

## 不快

痛い（場所）/ 苦しい / 痰 / 体の向き / トイレ / その他 →（暑い / 寒い / 喉が渇いた / かゆい / 眠れない）

**痛みの強さ**: 痛い場所を選ぶと、続けて「場所だけ / 少し / かなり / とても」を選べる。不快 → 痛い → 胸 → とても で「胸がとても痛いです。」（緊急色）が伝わる。「場所だけ」を先頭に置き、強さを選べなくても最短で伝えられる。

1画面の項目数は緊急・戻るを含めて8以内（requirements.md §4.1）。頻度の低い項目は「その他」に退避する。

## 快・要望

続けて / やめて / 変えて / 要望 → / 気分 →

- 二値の入口「続けて・やめて・変えて」を最上位に置く（編集できない固定項目）
- 要望 →: 大丈夫 / ありがとう / 眠りたい / 静かにしてほしい / 家族に会いたい / 話したい（テレビ・音楽などはフレーズ編集で追加できる）
- 気分 →: 不安 / さみしい / 落ち着かない

## 文字盤

最後の手段。清音 46 字 + 「ー」。行 → 文字の2段階スキャン。入力途中の文字列を常に大きく表示し、周囲の先読みを「はい / いいえ」で受ける。

## シングルスイッチ自動スキャン

- 起動時から常時動作。本人の入力は2経路だけ
- 任意キー / Bluetooth シャッターは同じオンとして現在のスキャン対象を実行する
- タイルの直接タップ/クリックは押したタイルを実行する（スキャン位置と無関係・二重実行しない）。画面の背景のタップは何も実行しない。タイルは role=button・aria-label を持つ
- スキャン間隔・先頭待機（既定は間隔の 4/3 倍＝1.5 秒間隔で 2.0 秒。Issue #92）・連打無視・押下時間の下限・決定タイミング・聴覚スキャンを介助者が設定（localStorage 保存）

## モールス入力（上級者向け・既定OFF）

介助者が設定で ON にしたときだけ、ホームの最後に「モールス」が出る。短押し＝短点・長押し＝長点で和文モールスの文字を入力する。SOS（・・・－－－・・・）を休まず続けて打つと即緊急。画面に操作と自動挙動の凡例を常時出す（requirements.md §4.7）。

## 触覚フィードバック

入力の受理・はい/いいえ・緊急・解除を、区別できる振動パターンで本人に返す。振動できない端末では、音声モードが OFF 以外、または設定「振動できない端末では、音声OFFでも短い効果音で知らせる」が ON（既定 OFF）のときだけ、短い効果音で代替する。緊急（呼び出し・呼び出し中）は効果音を出さず振動だけ（#43）。詳細は requirements.md §7.1。

## 常時案内

画面を見れば分かることは、どこにも書かない（Issue #79）。本人画面の下端には緊急中の振動の案内だけを出す（緊急でないときは何も出さない）。介助者メニュー上部には自動で起きること（60秒で閉じる等）を常に出し、「状態」タブの「いまの動作」には設定に応じた見ても分からない動作（連打無視・押し方・読み上げの割り込み）を出す。隠す操作はない（requirements.md §4.1.2）。

## 音声モード

- OFF
- 効果音だけ
- 短く読む
- 全部読む

相部屋や夜間に配慮し、デフォルトは OFF。緊急でも警告音は鳴らさない（視覚表示と振動で伝える）。

## 常設運用（画面スリープ防止・オフライン動作・全画面）

ベッド横に常設し、タイル直接タップと外部スイッチ（キー）で操作する運用を前提にした堅牢化（requirements.md §8, Issue #5）。

- **画面スリープ防止**: Screen Wake Lock API を起動時に取得し、タブが再表示されたときに再取得する。可視のままエラー/自動解放になった場合も、本人のスイッチ入力(タップ/キー)のたびと 30 秒間隔のタイマーで再取得を試みる。状態(有効/無効)を介助者メニューに表示し、非対応/失敗時は端末の自動ロックを切るよう促す
- **オフライン動作**: Service Worker がアプリ本体(HTML/JS/CSS/フォント/アイコン)をビルド時に丸ごと precache し、ネットワーク断・バックエンド停止でも緊急・はい/いいえ等の全伝達がオフラインで動く。ナビゲーションは3秒タイムアウト付き network-first で、失敗時はキャッシュへ確実にフォールバックする(precache自体がまだ無い初回アクセス等は、諦めずネットワークの応答を待ち続ける)。install が途中で失敗した場合は既存の版がそのまま動き続ける
- **オフライン準備の表示**: 介助者メニューの「オフライン準備: 完了/未完了」は、Service Worker がこのページを制御しているか(controller)だけでなく、現在ロードしているページが実際に参照している URL(`/` と JS/CSS。フォントは含めない — install は全件成功/全件失敗の一体なので、本体が揃っているならフォントも揃っている)が Cache に揃っているかまで確認して判定する。通常のクリック/タップで介助者メニューを開くたびに再計算し、未完了のあいだは Service Worker の更新チェック(既存の registration が無ければ再登録)を試みる。再試行の間隔は5分から始まり、失敗するたびに倍(上限60分)に伸ばす(指数バックオフ。完了すれば5分にリセット)。オフライン中(`navigator.onLine===false`)は無駄な再試行をしない
- **全画面**: PWA manifest は `display: fullscreen`(非対応環境では `standalone`)。介助者メニューの「全画面にする」でも同様の状態にできる(既に全画面のときはボタンを隠す)
- **誤作動防止**: ダブルタップ拡大・ピンチ拡大・pull-to-refresh・スクロール・テキスト選択・長押しコンテキストメニューを本人画面全体で抑止する。介助者メニュー内の操作は妨げない。orientation は縦横両対応(`any`)のため、横向き小画面で項目数の多い画面(文字盤等)の下段がビューポート外に出ることがあり、スキャン対象が変わるたびに画面内へ自動でスクロールする
